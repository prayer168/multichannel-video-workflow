# 風格導向動態圖文製作方法

本文件把公開可見的風格導向製作方法，轉成適用於 `motion-explainer-workflow` 的專案流程。目標是讓風格選擇、分鏡、渲染與檢查使用同一份可追溯規格；不是安裝或複製第三方影片工作室、風格畫廊、程式碼、素材或品牌。

## 適用範圍

使用者要求程式化動態圖文、動態標題卡、片頭動畫、短版資訊動畫、循環動畫，或需要先比較視覺風格再製作時使用。若只用現有 `build.py` 圖卡即可完成，留在主技能；若素材以實拍或螢幕錄影為主，使用 `video-editing-workflow`。

## 工作流程

### 1. 建立簡短製作 brief

先整理使用者已給的內容，再列出缺少且會改變設計的欄位：

| 欄位 | 記錄內容 |
|---|---|
| 用途與觀眾 | YouTube 片頭、解說段、Shorts、課堂展示等；觀眾看完要理解或採取什麼行動 |
| 畫布 | 比例、解析度、目標時長、幀率、是否需要無縫循環 |
| 畫面文字 | 必須出現的標題、數字、標籤；未知內容標待補 |
| 品牌與字體 | 頻道核定色彩、字體、角色與安全區；缺件不自行仿造 |
| 媒材 | 純圖形、使用者提供的照片／影片、已核准的示意素材或錄屏 |
| 音訊 | 旁白、原創或已授權音樂、靜音輸出與後製接合需求 |
| 交付 | 靜幀預覽、MP4、SRT、可編輯專案及驗收紀錄 |

未提供的欄位可先採本技能現有預設並標示；只有會大幅影響成果的未決事項才詢問。不要把一串固定問卷當作每個專案都必須逐題停下的關卡。

### 2. 定調一種視覺風格

沿用主技能已核定的材質模板、使用者提供的參考或本集新做的原創方向。需要比較時，以同一段旁白／同一組資訊製作 2–4 個風格樣幀，讓畫面差異可比較；確認後只保留一套主風格，避免每幕更換美術語言。提供「由你推薦」時，按題材、品牌和可讀性選擇並簡述理由，不要求使用者做不必要的選擇。

參考作品只拆解可觀察的設計屬性，例如色彩、層級、構圖、材質、動作速度與停留；不複製原作畫面、版型細節、角色、品牌或提示詞。使用者的品牌設定優先於風格參考。

將選定風格寫成單集 `STYLE_CARD.md`：

- 色板（HEX）、字體與中文字體來源、字級層級、底色和對比規則。
- 材質、線條、陰影、圖表、轉場和緩動方式。
- 允許的主要動作、每鏡視覺焦點數、字幕與品牌安全區。
- 禁用項、真實素材與示意素材的標示方式、素材來源／授權。
- 畫幅、解析度、幀率、時長、音訊與循環設定。

數值要具體且能檢查，但以本集內容和品牌規格決定，不直接照搬其他專案的 px、停留秒數或畫面字數限制。

### 3. 寫結構化分鏡

分鏡至少記錄以下欄位；可使用 Markdown 表格、JSON 或剪輯技能使用的 shot list，格式依專案選擇：

| 鏡號 | 時間／旁白事件 | 畫面目的 | 構圖與文字 | 素材 ID／來源 | 動作與轉場 | 驗收重點 |
|---|---|---|---|---|---|---|
| G01 | {起訖秒／旁白句 ID} | {此鏡讓觀眾理解什麼} | {層級、位置、標籤} | {素材路徑、授權、實證／示意} | {動作、方向、節奏} | {可讀、同步、來源等} |

鏡頭只寫可檢查的設計意圖，保留動畫實作空間。真實 UI 使用錄屏，不製作會被誤認為真實介面的假 UI。若 brief 或素材變更，回寫受影響的分鏡與預覽時間，不只改最終輸出。

若分鏡包含付費 AI 生成素材，另列服務、模型、片段時長、解析度、估算費用與素材來源；估價未知就明標未知。先把分鏡與費用給使用者，取得明確同意後才呼叫會扣點數或收費的生成服務。不得把費用估算當作已扣款或把失敗免費當作服務保證。

### 4. 保持時間軸可重現

程式動畫以可尋幀的同一時間來源驅動，例如 `renderAt(t)`／`setT(t)`，或 Remotion 的 frame-to-time 換算。所有元素都從同一時間軸計算位置、透明度和狀態；避免依賴播放時鐘、`Date.now()`、未固定種子的亂數或非同步計時器。需隨機變化時固定種子。旁白到齊後依實際配音時間修正，不能以文字長度代替音檔時間。

目前這是設計與交接規範，不代表 `build.py`、Remotion 專案或 HyperFrames 模板已內建通用的 brief／分鏡轉接器；實作前盤點目標專案的實際介面。

### 5. 先審靜幀，再擴展動畫

先為每段分鏡選取可重複取得的關鍵時刻：開場定場、資訊最密集處、主要動作完成、轉場落定、結尾狀態。產生靜幀條或聯絡表，依 `STYLE_CARD.md` 檢查視覺層級、文字裁切、字幕安全區、來源標示、角色連續性和旁白同步。先修正最影響理解的問題，再進入完整渲染。

簡單短片可用 3 張代表靜幀；較長或多場景影片需覆蓋每個分鏡的首尾與主要狀態，不把「三張靜幀」當全片固定通過條件。可請未參與製作的審片者提供觀眾視角意見，但最終仍需對照來源和全片回放。

### 6. 渲染與驗收

- 依已鎖定的畫幅、幀率、音訊規格和工具輸出；工具適用性依本機 preflight 與專案需求判斷。
- 依旁白語意、操作資訊密度和事件安排節奏；不以固定「不可停超過 N 秒」或「物件最短出現 N 秒」門檻取代教學判斷。
- 僅在作品本身需要無縫循環時，才比對首尾狀態／影格；普通解說片不強制首尾像素相同。
- 畫幅或時長與參考作品不一致時重新排版、重排時間，不直接裁切或拉伸成片。
- 回放最終 MP4 並檢查黑格、閃格、文字可讀性、字幕安全區、聲畫同步、品牌與片尾。修正後重跑受影響鏡頭及最終成片檢查。
- 自動像素差／節奏檢查只能當診斷提示；先看聯絡表，再聽看成片，依本集旁白、資訊密度和動作目的判讀。Harry Video Studio 的 `pacing_check.py` 預設用 1 秒最大變化間距與 0.3 秒最短停留作檢查，這是該專案的特定閾值，不直接移植成所有教學片硬規則。
- 沒有實際渲染或觀看證據，不宣稱檢查通過；性能與品質數據需記錄測試條件，不由單一樣片推廣為通用保證。
