# AI 輔助程式動態圖形與動態簡報

本流程把影片 [Gemini 動態簡報／圖形全攻略：提示詞 3 要素＋模型迭代](https://www.youtube.com/watch?v=uKmmvxW6KkM) 的方法拆成可控的製作步驟，適用於程式化動態圖形、圖解動畫與互動式 HTML 簡報。影片由 T客邦影新聞發布，長約 22:17；本分析以 YouTube 頁面、章節與可見逐字稿為主。逐字稿為平台自動轉錄，模型名稱、版本與能力依影片當時說法記錄，不當作現行產品規格。

## 影片方法摘要與採納判斷

| 時間 | 影片內容 | 工作流程採納方式 |
|---|---|---|
| 0:00–4:41 | 程式碼繪製的動態圖形、HTML 成品、旗艦與快速模型比較 | 小型獨立試作；模型比較只作個案，改用同條件 A/B 評估 |
| 4:42–7:26 | 提示詞三元素：視覺風格、實作技術、時間流程；機械蓮花分段動畫 | 納入可複製的 brief／prompt 結構與分段時間軸 |
| 7:27–12:57 | 先自我檢查迭代，再從好作品抽取 Markdown 配方，換新主題測試 | 加入具體審查迭代與「新專案／新題材」轉移測試；配方需人工審核 |
| 13:01–18:26 | GSAP 動態簡報：數字、遮罩標題、圖表、互動頁面與樣式轉換 | 當 HTML／GSAP 原型方法；需要交付影片時轉入既有 renderer 管線 |
| 18:27–22:17 | 同內容嘗試多種風格、模型成本與資源 | 多風格必須先核准並維持資訊層級、可讀性與品牌；成本／品質需實測 |

影片展示的亮點是「風格＋技術＋時間」的明確 brief、輸出後再檢查、以及在新題材驗證可重用規則。需謹慎看待的部分是每個模型只有少量示範，沒有控制變因、重複次數、品質量表或完整成本紀錄；影片中速度與品質差異只代表其示範樣本，不構成模型排名或普遍保證。所謂從成品「蒸餾」技能，是整理可重用設計規則，不等同訓練模型，也不保證跨題材成功。

## 建議製作順序

1. **定義交付物**：說清楚是互動 HTML 預覽、可編輯動畫專案，還是正式 MP4＋SRT。HTML 網頁不是 PowerPoint，也不會自動成為影片；正式影片沿用 HyperFrames／Remotion 與本技能既有音訊、字幕、品牌及驗收規則。
2. **先隔離試作**：在單集專案子資料夾產生 5–10 秒片段，記錄模型／工具、日期、依賴、輸出尺寸、畫幅、幀率和字型。不可直接寫入共用技能或正式素材目錄。
3. **寫可執行 brief**：至少指定內容目的、視覺方向、技術偏好（或讓模型提出並說明選擇）、時間分段、輸出契約和限制。例：`0–2 秒逐步畫出主體；2–6 秒依序展開 3 個有意義的結構；6–8 秒顯示標題並停留；全程 8 秒、16:9、可從任意 t 重現畫面。`
4. **檢查並迭代**：先開啟輸出實際看畫面，再讓模型列出具體可觀察問題（層級、構圖、動作意圖、文字溢位、中文字型、對比、同步、技術錯誤），依問題逐項修正。每輪保留版本與差異，不只下「更漂亮」等模糊指令。
5. **抽取專案配方**：高品質原型完成後，可整理單集 `MOTION_RECIPE.md`，只記錄可重用的抽象規則：視覺層級、線條／卡片處理、緩動選擇、進出場節奏、可重現時間軸與已知限制。將其放在該專案，不自動安裝為全域 Skill，也不把第三方程式、提示詞、作品、付費內容或品牌樣式原文複製進來。
6. **換新題材驗證**：用乾淨的複製專案及不同主題套用配方，檢查規則是否真的可泛化。至少由人檢查關鍵靜幀和成片；不通過就修訂配方，不宣稱「技能已驗證」。
7. **決定正式引擎**：HTML／SVG／CSS／GSAP 版面動畫優先用已支援的 HyperFrames；大量資料驅動或 React 元件重用時評估 Remotion。Three.js、Canvas、WebGL 可做畫面層，但須先在隔離目錄驗證可尋幀、無外網相依或已固定依賴、中文字型、音訊、幀率與渲染穩定性。正式畫面應以同一個 `setT(t)`／`renderAt(t)` 或 frame-to-time 函式驅動，避免依賴播放時鐘和非同步計時器。

## 動態圖形 Prompt 骨架

```text
任務／觀眾：{這個畫面讓觀眾理解什麼；對應旁白句 ID}
交付：{HTML 預覽／HyperFrames／Remotion；解析度、畫幅、時長、fps；是否需要音訊}
視覺方向：{色彩、材質、構圖、層級、參考屬性；不得仿製品牌或複製原作}
實作方式：{HTML/CSS/SVG/GSAP、React、Canvas/WebGL 等；若未指定請先提出選擇理由}
時間流程：{0–2 秒…；每階段的事件、進出場、完成後停留}
文字／資料：{逐字確認的標題、標籤、數值、來源；未知資訊標示待補，不要杜撰}
限制：{品牌固定項、真實素材與示意標示、字幕安全區、授權素材、不可使用項}
可重現性：所有視覺狀態由單一時間 t／frame 計算；固定亂數種子；提供指定時間點預覽方法。
驗收：列出技術錯誤、溢位／裁切、層級、可讀性、中文顯示、旁白同步、品牌及來源標示的檢查結果；不要自行宣稱未檢查項目通過。
```

## 模型／風格比較的實驗規則

需要比較模型時，固定同一 brief、素材、畫幅、時長、依賴和驗收量表；記錄每次實際耗時、重試、人工修改量與可用成本，最好對每個候選重複多次。比較敘事貼合、資訊正確、可讀性、動作品質、可編輯性、技術通過率和總成本，不以一次生成或自我評分選勝者。模型名稱、額度、價格和平台功能會變動，開案時依官方資料及實際帳戶重新確認。低成本模型可先負責小步修改，但只有達到同一驗收標準時才採用。

多風格探索每次只改視覺語言，保留內容、資料、層級、片長與品牌鎖定項；普普風等高刺激風格不得降低教學圖表、數據或繁體中文字的可讀性。黑熊老師、頻道色彩、片頭片尾與主技能固定設定優先，參考影片不授權我們複製其成品。

## 整合界線

- 先由 `awesome-ai-motion-integration.md` 找可研究的技法，再以本文件做隔離原型；再讀 `studio-style-production.md` 建風格卡與分鏡，依 `motion-graphics-ecosystem.md` 選正式 renderer。
- 如要交付 MP4，原型只供設計驗證；旁白到齊後重建／整理成可尋幀時間軸，使用現有正式渲染流程，並回到靜幀、整片、SRT、音訊、實證比例及品牌驗收。
- 不把 AI 生成的示意物件當實證，不製作仿真的真實介面；不要把未核對的 AI 生成數字或引用放進動畫。
- 本文件是從單一公開示範抽取的工作方法，非該影片的認證、模型效能基準或第三方 Skill 的再發布。
