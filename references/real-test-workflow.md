# 實測錄屏影片流程（AI 工具實測類）

> 來源：2026-10-09～10 首支實測集《AI 觀測站｜實測 Claude Mods》的實作紀錄。適用於「真的操作一個 AI 工具、錄下來、做成影片」的題目（AI Watch 為主；自然教室的數位工具實測也適用）。
> 規則優先順序不變：使用者本次指示 → `fixed-settings.md` → 頻道設定檔 → 本檔。

## 一、核心原則

1. **結論只能來自錄影。** 判定「AI 有沒有守住限制」「成功或失敗」之前，一定先回看完整錄影或對話紀錄；不能只看 git log、最後狀態或記憶。
   - 2026-10-09 踩坑：看到 git 紀錄有 commit＋push，誤判 Claude 違反「不要 commit／推送」。回看錄影才發現它已明說「沒有 commit、推送或部署」，是輸入框的灰色建議字被使用者按 Tab 接受、送出，它才照做，且每次只做被要求的那一步。腳本、字幕與進度紀錄全部依錄影更正。
   - 誤判一經發現，立刻告訴使用者、更正所有文件，並把「誰下了指令」本身變成影片的教學點，不要掩蓋。
2. **方案權限先確認。** 開拍前先確認使用者的方案能用到該功能（例：ChatGPT dots 需要 Pro／Business Premium，使用者是 Plus → 整集改為只實測 Claude Mods）。不可用假介面或模擬畫面補洞。
3. **數字全部可追溯。** 影片中的時間、行數、計數都要能指到錄影時間點或截圖；估計值要標「約」，待核對的列入缺件清單。

## 二、實測當天準備

- 給使用者一張可列印的「實測當天檢查表」（HTML 一頁）：每關的提示詞、要錄的畫面、驗收條件、預估時間。
- Claude Code 實測固定用手動確認模式開始：在 **PowerShell**（不是在 Claude Code 裡）輸入 `claude --permission-mode default`，畫面顯示「manual mode on」才開錄；不要用 auto／plan 模式，否則觀眾看不到確認畫面。
- 每關用乾淨的新資料夾與新對話（`/clear`），避免前一關的記憶或檔案影響結果。
- `claude` 找不到 → 用官方 install.ps1 安裝後重開 PowerShell。
- OBS：輸出資料夾固定一個（例：`桌面\aiwatch-錄屏`），格式 mkv（斷電不會整檔壞掉），錄完不改名，由 Claude 依時間戳對應插槽。
- 錄影長度：每關從貼上提示詞前 5 秒錄到驗收畫面結束後 5 秒；等待時間不用剪，後製快轉。
- 測試用 repo／網站：建立前先問使用者要公開或私人；完成後由使用者決定保留、改私人或刪除。

## 三、剪輯與合成（卡片框版）

- 版型：圖卡畫面中央挖一個透明「窗」（例：`BOX=(70,110,1240,698)`），實錄畫面縮放後放進窗內；右側留給步驟清單、計數面板與重點。觀眾同時看到實錄與解說。
- 做法：cairo 逐格畫圖卡，以 `OPERATOR_CLEAR` 清出窗口，輸出 BGRA → ffmpeg；實錄先依「片段表」裁切、變速、縮放，再 `overlay=0:0:alpha=premultiplied` 疊在圖卡下方。
- 片段表（每鏡一組，便於重剪）：`{鏡號: dict(segs=[(檔名, 起, 迄, 速度)], crop=(x,y,w,h), offset=秒, box=(x,y,w,h), until=秒)}`。
- **時間點一定要抽格確認。** 依記憶填的時間點常錯（例：以為是 Claude 畫面，其實是 YouTube 或 OBS 視窗）。每次改片段表就抽 1 fps 縮圖看過再渲染。
- 錄影中斷的 mkv（ffmpeg 回報 File ended prematurely）：先 `ffmpeg -i in.mkv -c copy out.mp4` 重新封裝再用。
- 等待段落以 1.6～2.4 倍快轉，畫面角落標示「快轉 ×2」，不刪掉等待的事實。
- 長指令會超過 10 分鐘限制：渲染、混音、壓縮分步執行。
- 傳給使用者看的預覽另壓一份分享版（`-preset medium -crf 30`，約 20 MB），避開 30 MB 傳檔上限；正式版留在專案。

## 四、旁白（Gemini Achird，在使用者電腦產生）

雲端容器連不到 Gemini，也沒有 Zhiwei。依 `fixed-settings.md` 第一節，由使用者在 Windows 產生：

1. Claude 依定稿腳本產生 `旁白資料.json`（只放黑熊老師要講的句子；角色台詞若由後製字卡處理就不放），連同 `scripts/build/產生旁白.py`、`產生旁白.bat` 一起放到使用者的專案資料夾。
2. 使用者確認已設定 `GEMINI_API_KEY`（`setx` 後要開新視窗），雙擊 `產生旁白.bat`。
3. 每組兩幕，間隔 21 秒（免費方案每分鐘 3 次、每天 10 次）；403／429 會停下，隔天再雙擊從缺的組接續。
4. 輸出 `配音/S01-S02.wav`…，Claude 再取回切成每鏡一檔、依旁白長度重排每鏡時間、配樂 ducking。

```json
{
  "style": "（fixed-settings.md 第一節 Style 全文，最後一行換成本片術語）",
  "scenes": {"S01": ["第一句", "第二句"], "S02": ["…"]},
  "pairs": [["S01", "S02"], ["S03", "S04"]]
}
```

也可以用 AI Studio 網頁版：同一份內容另存 `旁白稿_AIStudio.txt`（每組一段），使用者逐段貼上、Run、下載後依組名改名。

## 五、動畫（AI 影片生成）

角色動畫用 AI 影片生成工具製作，流程與提示詞見 `references/ai-animation.md`。實錄能說明的地方不用動畫；動畫只用在開場情境、角色登場、概念比喻與收尾。

## 六、交付節奏

- 預覽版本依序命名 `preview_v1`…，每版附 `缺件清單_vN.md`（要補的錄影、待核對數字、要使用者決定的事）。
- 預覽 chrome 標示版本與狀態，例：「預覽 v0.4（含實錄・無正式配音）」，避免被誤當成品。
- 正式組裝順序：黑熊老師片頭 4 秒 → 主片（右下角黑熊老師講課）→ 頻道核定片尾。
- 不自動上傳、公開或部署；需要付費的服務一律先問使用者。
