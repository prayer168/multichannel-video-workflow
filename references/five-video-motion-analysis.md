# 五支參考影片：旁白驅動的畫面變化

觀察日期：2026-10-23。依使用者提供的五個 YouTube 連結，以 Computer Use 抽看代表時間點；第 1、3、4 支另核對可匯出的時間碼逐字稿。這是抽樣分析，不宣稱已逐格觀看全片。第 2、5 支未取得可匯出的逐字稿，其旁白配對只記錄抽看畫面中可見的字幕和 UI。片中內容、數字及工具能力只視為影片呈現，不作獨立查證。下列方法可轉化為本技能的分鏡語法，不複製來源頻道的台詞、圖像或品牌版型。

## 逐片觀察

### 1. 翔宇工作流：長片 AI 剪輯的畫面組織

來源：[影片](https://www.youtube.com/watch?v=cRsNCh_HvsA&t=928s)，長約 29:32。

- **0:10–0:41（逐字稿）**：講者先讓觀眾看 AI 剪輯的成品，再說困難在元素排列、不同分鏡的「演法」及整片風格的統一。這裡的可採用方法是先展示成果、再拆解構圖規則；「風格一致」指視覺語法一致，並非每鏡採同一種滑入動畫。
- **12:56–14:30（逐字稿）**：明說先固定口播、清理氣口／口誤／重複句、生成 SRT，動效才知道要對在哪個詞或時段；改一個字可能牽動後方時間軸。這是來源講者提出的工作方法，適合轉化為本技能的聲畫鎖定流程。
- **[15:28](https://www.youtube.com/watch?v=cRsNCh_HvsA&t=928s)（實際畫面）**：米白紙感大畫布中間是一張「委派的提示詞」主卡，四張小卡從左到右標成思考、製作、優化、交付，各有短句與勾選符號；主卡右邊以細線接到機器人「子 Agent」。畫面下沿保留一排章節標籤，顯示目前所處段落。資訊由「任務目標 → 四步拆解 → 執行對象」構成路徑，觀眾能順著講解閱讀，不需每個元件同時飛入。
- **可轉用的視覺語法**：大畫布做持續的空間記憶；在旁白提到步驟時，局部卡片亮起、鏡頭推近或連線延伸；講完後停留完整關係圖。先在分鏡表標註每個關鍵詞應觸發哪個局部狀態，再選 Remotion／HyperFrames 動效。
- **限制**：此片其他章節在本次主要依逐字稿分析，不把每個敘述都稱作親眼看過的鏡頭。

### 3. Debug 土撥鼠：創意意圖、動畫成品、時間軸校準

來源：[影片](https://www.youtube.com/watch?v=yfQ3fucECME)，長約 6:36；有時間碼逐字稿。

- **[3:03–3:27](https://www.youtube.com/watch?v=yfQ3fucECME&t=183s)（逐字稿）**：講者舉「台北好吃、好玩、方便」的例子，要求 SVG 動畫加簡單標題，第一次成品有 101 卻不合想要的風格，因而重新描述為簡單乾淨。這說明提示詞須寫出構圖、材質、動作與排除項，並用代表鏡試風格。
- **[3:40–3:59](https://www.youtube.com/watch?v=yfQ3fucECME&t=220s)**：講者口述「Claude Code 和 Remotion 兩個 Logo 對撞，卡片向外展開」的創意想像。抽看的可見畫面主要是黑底的 Claude Code 提示框，逐漸打出這個動畫需求；因此「卡片爆開」在此首先是講者描述的設計意圖，不應把它當成本次已逐格核實的成品動作。
- **[4:32](https://www.youtube.com/watch?v=yfQ3fucECME&t=272s)**：真實 DaVinci 時間軸，上方預覽是「Remotion 做動畫要注意的三件事」與三張深色卡，下方是較長的綠色語音波形。旁白接著指出「動畫短、語音長」這個具體錯位；畫面本身就呈現問題，不需額外符號解釋。
- **[4:52–5:05](https://www.youtube.com/watch?v=yfQ3fucECME&t=292s)（逐字稿與時間軸畫面）**：先在三張卡出現點及淡出點切開視訊片段，然後把卡片的出現搬到旁白念「一、二、三」的位置，結尾淡出搬到語音尾端。這是內容里程碑對齊，並非平均拉長全段。
- **[5:09–5:30](https://www.youtube.com/watch?v=yfQ3fucECME&t=309s)**：時間軸留出的空缺透過慢放與凍結幀補滿。抽看影格可見影片切片分散在長語音波形之上，以及凍結幀／片段長度編輯處。方法是有內容時移動揭露點，沒有新資訊時讓已出現的畫面停住供觀眾讀取。
- **可轉用的視覺語法**：旁白先定稿；把動畫分成導入、各資訊點、退場等可拆片段。需要延長時優先保留可讀的完成狀態，避免為填滿時間而做無意義的持續運動。

## 跨片歸納：旁白如何讓畫面「跑動」

1. **畫面狀態跟隨語意狀態**：旁白從問題進到方法、從第一步進到第二步、從失敗進到成功，畫面才做對應切換。能沿用原構圖時，優先高亮、接線、展開或替換局部。
2. **關鍵詞是落點，氣口是緩衝**：一個詞或數字到來時，畫面完成揭露；其前後的語音提供動作起勢及閱讀停留。不是每個字都跳一下。
3. **兩種證據模式互補**：抽象卡片幫觀眾理解關係；真 UI、錄屏、原始資料幫觀眾確認實際操作或結果。切換時保留章節、色彩或構圖錨點。
4. **局部運動優先於全螢幕運動**：裁切放大、游標停留、框選、狀態變色、路徑亮起，往往比整頁元素持續飛動更能準確配對一句旁白。
5. **延長畫面是設計動作**：當旁白比動畫長，先調整揭露點，再以可讀的完成狀態、慢動作或凍結幀補足；不可讓空畫面或無關循環動畫硬撐。
6. **風格有一致的語法，也有鏡頭變化**：字體、色彩、材質、標示與轉場規則一貫；證據錄屏、概念圖、局部特寫與全貌圖按目的切換。
7. **製作本技能影片時遵守現行設定**：參考片中的燒錄字幕只能作為觀察，不照搬。本技能 2.13.0 起正式片只交付影片及獨立單行 SRT；畫面中的短標籤、圖例和數字是教學圖形，不能重複整句旁白作常駐字幕。

## 可加入技能的製作提示詞

```text
你是「旁白驅動的動態解說」分鏡導演與動畫／剪輯實作者。請根據已定稿的旁白做畫面，讓觀眾在關鍵詞出現時看見相應的關係、操作或狀態改變。先讀 multichannel-video-workflow 的 SKILL.md、references/fixed-settings.md、對應頻道 profile、references/subtitle-style.md、references/narration-led-visuals.md、motion-explainer-workflow/SKILL.md；以上現行設定及使用者本次指示優先。

輸入：{頻道與影片目的}、{已定稿旁白音檔與逐句時間碼／SRT}、{章節}、{真實錄屏／照片／數據與來源}、{核定品牌資產}、{比例／解析度／幀率}、{已核定的風格方向}。

請先建立一張逐句「視覺事件表」：旁白 ID、起訖時間、語意功能、關鍵詞與精確落點、畫面起始狀態、這句只變動的一個主元素、主視覺動詞、動作完成狀態、觀眾需要讀取的停留長度、下一句如何沿用或離開此狀態。把問題／定義／流程／因果／比較／操作／證據／轉折／限制／總結分清楚。畫面變化需回答「這句話令哪個關係變得可見？」

對每個鏡頭設計：
1. 先給觀眾辨認整體空間的位置，再逐句高亮、連線、展開、裁切放大或替換局部；若重用概念地圖，保持導覽錨點，讓狀態逐步累積。
2. 關鍵詞到達時才讓對應卡片、步驟、數字、游標或圖表線條完成揭露。用氣口讓畫面呼吸；資訊密集時停留，勿逐字跳動或無故持續漂移。每個氣口一個主動作。
3. 真實工具、按鈕、成品或數據用可追溯錄屏與來源；只在旁白談到該處時局部放大、框選或停住。示意圖明標「示意」。真 UI 與概念圖切換時保留章節或視覺錨點。
4. 比較時讓共同基準對齊；因果時依序顯示前因、動作、後果；步驟時完成上一階段才亮起下一階段；失敗／成功必須有可辨的不同狀態，不只靠顏色。
5. 如果旁白長過預製動畫，先切開各內容揭露點，移到對應詞句；用停格、完成狀態或合理的慢動作填充閱讀時間。不要重複無關動畫或讓畫面過度閃動。
6. 統一字體、材質、色彩角色、圖表尺度、鏡頭速度與標註；讓景別與媒材依敘事功能改變。選 Remotion 或 HyperFrames 時，依現有工具規則與代表鏡測試結果決定，不因參考片使用某工具就硬套。
7. 不照抄參考影片的 Logo、台詞、構圖、素材或獨特包裝；不捏造實測、UI、數據和結果。不把旁白文字整句燒在畫面上。遵守本技能的獨立 SRT、字幕安全區及頻道固定設定。

先製作一段同時含概念圖、局部動作、真實證據或必要的示意、以及一次轉場的代表段，交付靜幀條或預覽；若使用者已授權完整製作，直接依規則完成全片。最後逐鏡檢查：語音與畫面是否在同一意義上同步？元素有沒有在觀眾看清前消失？真實畫面是否可追溯？比較尺度是否公平？停留是否有理由？移除某動效後若理解不受影響，刪除它。

輸出：視覺事件表、逐鏡分鏡表、Remotion／HyperFrames 實作分工、素材來源表、代表段預覽／靜幀條、完成片與獨立 SRT、聲畫對齊及畫面安全區檢查結果。
```
