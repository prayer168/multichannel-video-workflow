# 製作實務筆記（自動粗剪、浮水印、常見陷阱）

> 來源：上集《打造我的影片技能》粗剪的實際經驗（2026-09-29）
> 參考實作：使用者工作區 `10_建置過程影片/上集_打造我的影片技能/2_製作中/剪輯專案/`（`cards.py`、`assemble.py`、`thumbnail.py`、`say_batch.ps1`）

## 一、沒有螢幕錄影時的「自動粗剪」流程
1. **逐句旁白稿**：`旁白稿_分場.md`，每幕一個 `## Sxx 標題`，一行一句
2. **暫定配音**（沒有 TTS API 金鑰時）：Windows 內建臺灣國語語音 Zhiwei（OneCore）
   - 一般的 System.Speech 叫不到 OneCore 語音 → 用 WinRT `Windows.Media.SpeechSynthesis`，並以 **powershell.exe 5.1** 執行（pwsh 7 不支援 WinRT 投影）
   - **逐句**產生 wav → 每句時間精準，字幕與畫面都能對齊
   - 語速 `SpeakingRate` 約 1.2 → 每分鐘約 225 字（比正式配音慢，只用來抓時間）
3. **圖卡**：用 Pillow 產生 1920×1080 品牌圖卡（標題卡、大數字、清單、流程、對照、對話框、圖片卡）
4. **畫面段落表**：每幕列出「從第幾句開始 → 哪張圖卡／哪段影片」，約每 10–20 秒換一次畫面
5. **組合**：修剪每句頭尾靜音 → 串成配音軌（句間 0.22 秒、句號後 0.45 秒、換幕多留 0.5–0.6 秒）→ 產生 SRT → 圖卡做緩慢推近（zoompan，約 3.5%）→ 串接 → 片頭＋浮水印＋音訊
6. **正式配音替換**：正式配音若是「逐幕」音檔，要先用靜音偵測或強制對齊切回逐句，再重新組合

## 二、浮水印規則
- **兩種做法擇一**：剪輯時疊加 `浮水印_疊加用_1920x1080.png`，或上傳 YouTube 工作室「影片浮水印」。兩個都用會出現兩個熊掌
- **影片素材段落要關閉疊加浮水印**：片頭、熊掌動畫、示範影片本身已經有熊掌 → 用 overlay 的 `enable='not(between(t,a,b))'` 避開
- 會推近（Ken Burns）的圖卡裡**不要放徽章**：推近時圖中徽章會移位，和固定浮水印形成疊影
- 片頭用「縮到角落」版時，片頭結束的徽章位置＝浮水印位置，可以無縫銜接

## 三、常見陷阱與解法
| 陷阱 | 解法 |
|------|------|
| 微軟正黑體沒有 ✓ ✗ ▸ 與 emoji，會顯示成方框 | 勾勾、叉叉用線條畫；符號改用「・」；不要用 emoji |
| 每張圖卡「從黑色淡入」→ 換圖時閃黑 | 直接切換（符合本風格：硬切或溶接） |
| ffmpeg `-ss` 搭配 `-stream_loop` 只對第一輪有效 → 循環時從頭播 | 靜態畫面改用圖片；或先切出片段再循環 |
| 圖片用 `-loop 1` 再接 zoompan → 影格數暴增 | 圖片不要 `-loop`，zoompan 的 `d` 設成總影格數 |
| overlay 疊無限循環的圖片 → 輸出沒有結束 | overlay 加 `shortest=1` |
| 單次 loudnorm 後整體只有 -17 LUFS | 先量測整合響度 → 補增益 → 限幅器（alimiter）→ 再量測一次 |
| 指令列中的 `\n`、中文字串比對失敗 | 用編輯工具或獨立的 .py 補丁檔，不要在 heredoc 裡做字串替換 |
| 示範影片開頭本身含片頭 → 開場重複播片頭 | 抽取靜態畫面，或從適當時間點切出 |

## 四、品質檢查（輸出後必做）
- `ffprobe`：長度、解析度、影格率
- `ebur128`：整合響度約 -14 LUFS、峰值 < -1 dBFS
- `blackdetect`：沒有意外的黑畫面
- 抽樣檢查畫面：片頭、每幕第一張圖卡、影片素材段落、結尾；特別看右下角浮水印有沒有重複或疊影
- 縮圖縮小到 320×180 檢查主標是否可讀
