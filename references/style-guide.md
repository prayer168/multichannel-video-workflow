## 風格七大支柱

> ⚠️ **我們的版本（2026-09-29 決定）：** 開場白與結語**不使用 Papaya 的原句**（避免版權與辨識度問題），改用黑熊老師的問候語：開場「哈囉，大家好，我是黑熊老師。」；結語「…我是黑熊老師，感謝大家觀看這部影片。如果你希望黑熊老師接下來拍什麼影片，請在底下的留言區留言告訴我。我們下次見，掰掰！」。本報告保留 Papaya 原句，只作為研究紀錄。

| 5 | **溫和、口語、穩定的旁白** | 每分鐘約 310 字，每句 12–13 字，用「好，」切段，用「囉／喔」收尾 | 06 |

## 為什麼「看起來活潑、抓眼球，又很有脈絡」？

1. **脈絡來自結構**：每支影片都是「情境 → 準備 → 功能 1…N → 進階應用 → 收尾」，章節標題就是目錄，觀眾隨時知道自己在第幾步。
2. **活潑來自視覺換氣**：大約每 20–40 秒就換一次畫面性質（錄影 → 插畫 → 錄影 → B-roll → 動畫圖卡），而且螢幕錄影本身也不靜止，一直在推近、拉遠。
3. **親切來自語氣**：從來不賣弄術語。遇到術語一定緊接著「也就是所謂的…」「你可以把它想成…」，用白話解釋。
4. **抓眼球來自開場的「秀成果」**：先讓觀眾看到最炫的成品或官方宣傳片段，才進入安裝步驟。

## 關於「對嘴 AI 配音」和「貼圖」的觀察（重要）

- 這 6 支樣本的畫面中，**沒有看到對嘴的虛擬主播或卡通角色**。旁白是畫外音，聲音自然、語調平穩，但無法從影片本身判斷是真人錄音還是 AI 配音。
- 「貼圖」在近期影片中的樣子是：
  - **AI 生成插畫**（Pixar／日系柔和 3D 風格），會做成輕微動態（image-to-video）
  - **故事角色**：例如 LLM Wiki 那支的高中生「小杰」，在章節轉換時反覆出現
  - **UI 標註**：網址標籤、TIP 角標、紅色箭頭、圈選
- **決定（2026-09-29）**：不使用對嘴角色，全片只用畫外音旁白，與 Papaya 一致。

## 風格演變（2020 → 2026）

| 項目 | 2020 Power BI 時期 | 2026 AI 工具時期 |
|------|-------------------|-----------------|
| 開頭招呼 | 「哈囉，大家好」 | 「嗨，大家好」 |
| 片頭 | 簡單的扁平圖示輪播 | 品牌 Logo 動畫，加上官方宣傳片或 AI 插畫蒙太奇 |
| 畫面 | 純 Windows 螢幕錄影，搭配「直條圖」這類白底文字卡 | Mac 錄影、鏡頭推拉、AI 插畫、B-roll、網址標籤 |

| 轉場口頭禪 | 「OK，」 | 「好，」為主，「OK，」為輔 |

# 01 頻道定位與選題策略

## 受眾
- 一般上班族、教師、學生、自由工作者，也就是「會用電腦，但不是工程師」的人
- 標題常用「沒有程式基礎也沒有關係」「保姆級」「新手生存指南」「從零到精通」，降低進入門檻

## 選題類型（近 40 支統計）

| 類型 | 占比（約） | 例子 |
|------|----------|------|
| AI 助理實作（Claude / Codex / ChatGPT / Gemini） | 45% | Claude Skill 省訂閱費、Claude Code 保姆級、Codex 包辦 Office |
| 免費／開源神器推薦 | 20% | God's Eye View、Mole、Handbrake、Affinity、Hugging Face |
| 生產力軟體（Notion / Obsidian / Excel / Word / SharePoint） | 20% | LLM Wiki + Obsidian、Excel 動態時間軸、Word 多層次清單 |
| AI 影像與動畫創作 | 15% | ComfyUI、Suno + Nano Banana + Kling MV、Remotion |

## 兩條產品線

| | 長片（主力） | 短片 Ep.xxx 系列 |
|---|---|---|
| 長度 | 10–27 分鐘（大多 11–18 分鐘） | 2–6 分鐘 |
| 標題 | 沒有編號 | 結尾加上「(Ep.126)」 |
| 內容 | 一個完整專案或保姆級教學 | 一個小技巧、一個新功能 |
| 縮圖 | AI 生成的電影感主視覺 | **固定的黃色模板** |
| 權限 | 公開 | 部分限頻道會員觀看 |

## 選題公式
一個好題目要同時滿足下面至少 3 項：
1. **有熱度**：最近推出或爆紅的工具（「國外瘋傳」「迎來重大升級」「出大招了」）
2. **有省錢角度**：免費、開源、取代訂閱（「0 元」「省下上千元」「退訂 Adobe」）
3. **有具體成果**：看完能帶走一個 App、一個網站、一套工作流
4. **有可展示的畫面**：3D 地球、動畫、圖表這類「一看就哇」的東西
5. **能串接**：A 工具 + B 工具的組合拳（「Claude 串接 Higgsfield」「ChatGPT + Figma 組合拳」）

# 02 標題與說明欄公式

## 一、標題結構

**【鉤子句（痛點／反問／驚嘆）】＋【工具名】＋【動詞：讓你／幫你】＋【具體好處】＋【情緒收尾】**

標題長度大多 40–60 個中文字，用全形「？」「！」切成 2–3 段。

### 五種鉤子句型（附原標題）

| 句型 | 公式 | 原標題 |
|------|------|--------|
| A 痛點反問 | 還在 ＿＿？ | 還在用 PPT 製作廉價簡報動畫？Claude Design 2.0 迎來重大升級… |
| B 禁止句 | 別再 ＿＿！ | 別再小看本地 AI！Gemma 4 + LM Studio 讓你的電腦變成超級離線 AI 工作站 |
| C 顛覆宣言 | 這款 ＿＿ 將顛覆你對 ＿＿ 的認知！ | 這款開源軟體將顛覆你對地圖的認知！用語音操控上帝視角… |
| D 第一人稱成果 | 我用 ＿＿ 省下了 ＿＿！ | 我用一個 Claude Skill 省下了所有生成圖片和影片的訂閱費用！每個月現省上千元！ |
| E 熱潮／懸念 | 國外瘋傳的 ＿＿！／OpenAI 為什麼 ＿＿？ | 國外瘋傳的 AI 筆記工作流！LLM Wiki 讓你的 Obsidian 筆記升級成… |

### 好處段常用詞
- 數字：「6 個小技巧」「7 大核心功能」「縮小 80%」「省下 80% 的行政時間」「每個月現省上千元」
- 速度：「一秒掌握」「秒抓重點」「一分鐘搞定」「一鍵上線」
- 門檻：「保姆級教學」「沒有程式基礎也沒有關係」「只要會『許願』就可以了」
- 誇飾比喻：「上帝視角」「情報局等級」「第二大腦」「軍火庫」「神仙組合」「零薪水管家」

### 情緒收尾
「用過就回不去了！」「看完後恍然大悟了！」「就可以了喔！」「而且完全免費（手機也能使用喔！）」
偶爾用「~」表示語氣輕鬆，例如「每天解鎖都是驚喜 ~」。

### 引號用法
關鍵概念用「」框起來：「許願」「做給 AI 看」「縮小 80%」「動畫工作流」。

```
🔹 內容綱要
00:00 章節一
01:48 章節二
...

🔹 提示詞連結          ← 有提供提示詞時才加
https://papayaclass.s.gy/xxxx

🔹 網站連結
工具名 https://...
工具名 https://...

🔹 請 Papaya 喝咖啡 ☕️
https://buymeacoffee.com/papayaclass

```

**重點**
- 說明欄沒有長篇介紹，第一行直接是章節。
- 章節一定要有時間碼（YouTube 會自動切成章節）。
- 提示詞、練習檔放在短網址後面，這樣可以導流也可以追蹤點擊。
- Hashtag 第一個固定是 `#教學`，接著是工具名。
- 標籤（tags）大約 7–8 個：教學、工具名、AI、相關概念。

## 二之一、我們的 SEO 調整（與 Papaya 刻意不同，2026-09-29 決定）
- 標題：保留鉤子句型，但**主要關鍵字要在前 40 字內**
- 說明欄：在「🔹 內容綱要」之前**加上 1–2 句含關鍵字的摘要**（Papaya 沒有）
- 章節名稱：盡量使用觀眾的搜尋詞
- 詳見 `03_影片製作工作流/SEO規範.md`

## 三、章節命名規則
- 名詞片語，不寫成句子：「設定專案資料夾」「取得 API 金鑰」「即時航班圖層」
- 技巧型影片用「技巧 N：主題 (補充)」：「技巧 1：建立設計系統 (Design System)」
- 英文專有名詞保留原文，必要時括號附中文
- 一支影片大約 6–10 個章節，每章 1–3 分鐘

# 03 縮圖設計規範

> 樣本：`02_參考素材/縮圖樣本/近期縮圖總覽_01-20.jpg`、`_21-40.jpg`

## 共同原則（兩種版型都適用）
1. **沒有人臉**：沒有驚訝表情，也沒有真人。
2. **最多兩層文字**：主標是工具名或核心概念（1–6 個字），副標是一行好處（6–12 個字）。
3. **主標不重複影片標題**：標題負責講故事，縮圖只負責讓人一眼認出主題。
4. **大量留白**：主體占畫面約 40%，文字占 30–40%，其餘是背景。
5. **不塞箭頭、不塞紅圈、不塞 emoji**，所以看起來很乾淨。

## 版型 A：黃色模板（Ep. 短片、會員影片）

```
┌──────────────────────────────────────────┐
│ [App圖示]                    ═══○═══     │  ← 左上：圓角方形 App 圖示
│                              ─────       │     右上：線條與膠囊形裝飾
│                                          │
│     ChatGPT 瀏覽器                        │  ← 主標：黑色圓黑體、白色描邊、陰影
│                  (高手也會忽略的強大功能！) │  ← 副標：黑色膠囊，白字
│  ─ ──                  ~~~淡黃色大弧形~~~  │  ← 左下短橫線、右下淺色色塊
│               ───────────────            │
└──────────────────────────────────────────┘
```

| 元素 | 規格 |
|------|------|
| 背景 | 主黃 #FFC72C 左右，右下角有更淺的黃色大弧形（#FFD95A） |
| 主標字體 | 圓潤的粗黑體（類似「粉圓體 Bold」「jf open 粉圓」「源泉圓體 Heavy」），英文用較粗的圓體或 Cooper 風格 |
| 主標樣式 | 深灰黑 #2B2B2B、白色描邊 6–8px，再加一層灰黑外陰影 |
| 副標 | 黑色 #222 的圓角膠囊，白字 20–24pt，放在主標右下 |
| App 圖示 | 左上角，圓角 20%，帶陰影 |
| 裝飾 | 右上兩個細線膠囊外框加橫線、左下兩條短橫線、底部一條細長橫線，顏色都是深灰，線寬 2px |

## 版型 B：主視覺模板（長片）

- **背景**：AI 生成的電影感 3D 或產品攝影畫面（例如場記板、3D 地球 HUD、書本加光點、機器人、數位雕塑）
- **配色**：一支影片只用一個主色調（橘紅、深藍黑、紫、青綠），跟工具的品牌色一致
- **文字位置**：放在左半邊或正中央，主體物件放右半邊
- **主標字體**：
  - 科技感：乾淨的無襯線粗體（例如 Noto Sans TC Black、Inter Bold）
  - 活潑感：圓體加白色描邊（同版型 A）
  - 特殊主題：金屬發光字（上帝之眼）、描邊漫畫字（Hermes Agent）
- **副標**：細字或小膠囊、細橫線裝飾，常寫成中文加英文（例如「Excel Dynamic Timeline」）
- **品牌 Logo**：有時放在主標上方的小字（例如「Microsoft」「Codex」）

## 縮圖文案公式
| 主標 | 副標 |
|------|------|
| 工具名 | 用途或定位（「全能 AI 桌面助理」「開發者必學神器」） |
| 核心概念 | 好處數字（「省下 80% 閱讀時間」） |
| 顛覆型大字 | 補充說明（「0元」＋「自己的電腦就能生成 AI 影片！」） |
| A × B | 組合後的成果（「CLAUDE × HIGGSFIELD」＋「大師級動畫工作站」） |

## 製作流程建議
1. 用 AI 生圖（Nano Banana、Midjourney、GPT-Image）產生**不含文字**的主視覺，並在右側留出空白
2. 到 Canva、Figma 或 Photoshop 套用 `04_品牌資產/縮圖模板/`（版型 A 或 B）
3. 用手機大小檢查：縮小到 160×90 時，主標還看得清楚嗎？

# 04 片頭與開場結構（前 60 秒）

## 時間軸拆解（實測 jn7UXxa1Llg、ZC8AI_jFWnU、tlEnf7P7wDA）

> ⚠️ **我們的版本（2026-09-29 決定）：** 片頭改用自己的「黑熊老師品牌片頭」（黑板＋粉筆畫出黑熊老師＋胸前白色 V 字＋M1 尤克里里品牌音樂，無人聲，約 4 秒），刻意避開 Papaya 的米白底、紅藍筆刷、藍色方塊與圓環；主講旁白在片頭結束後才開始，不和片頭重疊。規格見 `04_品牌資產/片頭動畫/片頭規格.md`。

| 時間 | 畫面 | 聲音 |
|------|------|------|
| 0.0–0.5s | 米白底（#E9E5DE），一紅一藍兩道筆刷弧線飛入 | 片頭音效開始 |
| 0.5–1.5s | 弧線收束成藍色方塊「P」Logo（藍 #1E9BE0，帶立體陰影），外圍有同心圓環和放射刻度線擴散 | 音效高潮（hit） |
| 1.5–2.5s | 背景轉成純白，圓環淡出，四周飄著彩色小碎片 | 餘韻 |
| 2.3–4.5s | Logo 往左移，右側滑入「PAPAYA 電腦教室」字樣，下方淡灰細線 | 餘韻結束 |
| 約 2.9s | ——（仍在片頭） | **旁白第一句「嗨，大家好」** |
| 4.5s 起 | 切入**主題開場蒙太奇** | 旁白講述 |

> 片頭總長約 4.5 秒。旁白在第 2–3 秒就開始講話（跟片頭重疊），所以一點都不拖沓。

## 開場蒙太奇（約 4.5s–20s）的三種素材
1. **官方宣傳片段**：例如 Claude Design 官方影片的桌面場景、產品 UI 動畫
2. **社群熱度證明**：推文、討論串截圖拼貼（LLM Wiki 那支的 9 秒處）
3. **主題標題卡加 AI 插畫**：
   - 工具名標題卡，例如深色粒子背景上的「Obsidian」、漸層背景上的「LLM Wiki」
   - AI 生成的情境插畫，而且是動態的（女孩配 AI 機器人、未來圖書館），用來解釋概念
   - 電影感 HUD 畫面（上帝之眼的 3D 地球、戰情室介面）

**原則：前 20 秒先秀成果或世界觀，不秀安裝畫面。**

## 開場旁白公式（約 20–40 秒）

> ⚠️ **我們的版本（2026-09-29 決定）：** 開場白與結語**不使用 Papaya 的原句**（避免版權與辨識度問題），改用黑熊老師的問候語：開場「哈囉，大家好，我是黑熊老師。」；結語「…我是黑熊老師，感謝大家觀看這部影片。如果你希望黑熊老師接下來拍什麼影片，請在底下的留言區留言告訴我。我們下次見，掰掰！」。本報告保留 Papaya 原句，只作為研究紀錄。

```

② 背景/痛點： [最近 X 很紅 / 平常我們要做 Y 必須…，這對…來說是一個不小的負擔]

④ 一句定義：  你可以把它想成是「…」 / 這個軟體把…全部整合到…

# 05 影片段落結構（全片骨架）

## 標準骨架

```
[0] 片頭 Logo 動畫                          0:00–0:05
[1] 開場：招呼 + 痛點 + 介紹 + 承諾            0:03–0:40
[2] 環境準備：下載 / 建立專案資料夾 / 註冊 / 取得金鑰   約 1–4 分鐘
[3] 核心功能 1 ─┐
[4] 核心功能 2  ├─ 每段 1–3 分鐘，一段一個章節
[5] 核心功能 N ─┘
[6] 進階 / 客製化：請 AI 幫你擴充（在地化、改造成 App）   高潮
[7] 成果展示（互動 Demo，例如語音操控、播放成品）
[8] 收尾：「那今天關於 X 的介紹，我們就聊到這邊…拜拜」   5–10 秒
```

## 三種常見敘事模式

### 模式 A：「圖層巡禮型」（God's Eye View）
工具內建很多功能，就一個一個打開來介紹，**由宏觀到微觀**：
全球（衛星、太空）→ 城市（街景、車流）→ 在地化（切到台灣、台北）→ 高潮（駕駛艙視角、AI 語音）

### 模式 B：「技巧清單型」（Claude Design 6 技巧）
標題先承諾數字 N，章節命名為「技巧 1：…」，並且在畫面右下角放「TIP N ○○」角標。
每個技巧都遵循：**為什麼需要 → 怎麼做 → 做出來的效果**。

### 模式 C：「故事主角型」（LLM Wiki + Obsidian）
設定一個虛構主角（「小杰，一個喜歡三國歷史的高中生」），用他的需求串起所有操作：
「於是小杰點擊…」「小杰打算…」。主角的 AI 插畫會在章節轉換時出現，**把枯燥的操作變成劇情**。

### 模式 D：「從零建置型」（Claude Skill、自己做 App）
建立資料夾 → 取得金鑰 → 建立功能 1 → 優化 → 加入功能 2 → **最後把成果打包成桌面 App**（常見的高潮收尾）。

## 每個章節內部的微結構

```
「好，」＋ 本段主題一句話          ← 轉場標記
為什麼（痛點或用途）1–2 句
操作步驟：點擊…→ 選擇…→ 按下…     ← 動詞開頭，一句一個動作
等待句：「過了一會兒 / 稍待片刻後」  ← 剪掉等待時間
成果句：「…就能…囉」               ← 用正向語氣結尾
（選用）小提醒：「不過…」「如果你…的話」
```

## 節奏數據

| 指標 | 數值 |
|------|------|
| 章節長度 | 平均 1.5–2.5 分鐘 |
| 「好，」轉場頻率 | 平均每 35–45 秒一次（每支 13–19 次） |
| 畫面性質轉換 | 約每 20–40 秒一次 |
| 片長 | 長片 11–18 分鐘最常見 |

## 高潮設計
每支影片的最後 1–2 個章節一定是「最酷的東西」：
- 上帝之眼：駕駛艙第一人稱降落，接著是 AI 語音導覽台北 101
- Claude Design：在講者影片上自動疊加動畫（子母視窗）
- LLM Wiki：自動產生互動式 HTML 資訊圖表
- Claude Skill：包裝成桌面 App

旁白會先預告：「好，最後我們來看一個很酷的功能」「最後要跟大家分享一個很酷的技巧」。

# 06 旁白語氣、節奏與口語詞庫

## 一、量化數據（依 5 支人工字幕逐字稿統計）

| 影片 | 時長 | 字數 | 每分鐘字數 | 每句平均字數 | 以「好，/OK，」開頭的句數 |
|------|------|------|-----------|-------------|------------------|
| Claude Design 2.0 | 12:52 | 4139 | 321 | 13 | 18 |
| 上帝之眼 | 10:45 | 3285 | 305 | 13 | 18 |
| Claude Skill | 13:15 | 4146 | 312 | 13 | 19 |
| LLM Wiki | 18:03 | 5625 | 311 | 12 | 19 |
| Power BI（2020） | 14:48 | 4350 | 293 | 12 | 6 |

**➜ 目標語速：每分鐘約 300–320 字，每句 10–15 字（一句就是一行字幕）。**
這比一般 YouTuber（每分鐘 350–400 字）慢一點，屬於「穩、清楚、聽得懂」的教學節奏。

## 二、聲音特質
- 男性，中音偏低，咬字標準的台灣國語，不捲舌也不誇張
- 情緒：**溫和、微笑感、平穩**，沒有大起大落，也不大喊
- 句尾常輕輕上揚（「囉」「喔」），帶一點親切感
- 停頓：每句之間約 0.2–0.4 秒；「好，」之後停頓稍長，當作段落呼吸
- 人稱：主要用「我們」（帶著你一起做），「你可以」（給選擇），「我」只用於示範（「這邊我選擇…」）

> AI 配音建議：選擇「溫暖、沉穩、台灣腔、男聲、敘事型」的聲線，語速設 0.95–1.0x，風格選 calm 或 narration，不要選 energetic。

## 三、口語詞庫

### 1. 轉場（段落開頭）
| 詞 | 用途 | 頻率 |
|----|------|------|
| **好，那…** | 最主要的段落切換 | ★★★★★ |
| **OK，** | 階段完成、要收尾時 | ★★★ |
| **那** | 句首接續（「那目前…」「那這邊…」） | ★★★★★ |
| 接著 / 然後 / 再來 | 步驟串接 | ★★★★ |
| 除此之外 / 此外 | 補充功能 | ★★ |
| 好，看完了 X，接著我們不妨來… | 大段落切換 | ★★ |
| 好，那下一個我們要介紹的小技巧是… | 清單型 | ★★ |
| 好，最後我們來看一個很酷的功能 | 高潮預告 | ★ |

### 2. 舉例
「舉例來說」「譬如」「例如」「像是 A、B 和 C 等」「假設今天我想…」

### 3. 操作動詞（精準、固定）
- 點擊「X」／按下「X」／雙擊滑鼠左鍵／點擊滑鼠右鍵
- 拖曳／拷貝起來／按下 Ctrl + V 執行貼上
- 按下 Enter 鍵將提示詞送出
- 到右上角／左下角／側邊欄 找到…
- 把目前的專案指定到剛建立的資料夾
- **UI 名稱一律用「」括起來**：點擊「儲存」、選擇「動畫」

### 4. 等待與跳剪
「過了一會兒」「稍待片刻後」「等 Claude 實作完畢後」「安裝完成後」「素材蒐集完畢後」

### 5. 成果句（正向收尾）
- …就 OK 了
- …就能…**囉**（最具代表性）
- …就會立即…**喔**
- 如此一來，…
- 於是我們就能看到…
- 是不是非常地方便呢？

### 6. 解釋術語
- 也就是所謂的「…」
- 你可以把它想成是「…」
- 中文直譯的話叫做「…」
- 英文 + 括號中文：Effort (努力)、Present (播放)、Get Key (取得金鑰)

### 7. 安撫與貼心提醒
「也不用擔心」「遇到這種情形不用著急」「如果你拿不定主意，你也可以…」「如果不想要有這筆額外的支出，則可以考慮…」「不過這些光點只是…無法反映出真實的…」

### 8. 評價形容詞（克制，而且有具體理由）
「非常有意思」「很酷」「很有趣」「最酷的是」「別有一番懷舊的風味」「看起來專業且吸睛」「質感很棒」
**注意：不說「超級無敵」「炸裂」「神到不行」**，誇飾只出現在標題，不出現在旁白。

## 四、句型節奏範例（可直接套用）

```

## 五、寫稿規則（給 AI 產生腳本用）
1. 每行 ≤ 16 字，一行就是一句字幕

7. 需要等待的地方一律寫「過了一會兒」，剪輯時直接跳剪

# 07 視覺剪輯與畫面語言

> 影格證據：`02_參考素材/影格截圖/*_sheet*.jpg`（YouTube storyboard，每格間隔約 5 秒）

## 一、畫面素材的四種類型與比例（長片）

| 類型 | 比例 | 用在哪裡 |
|------|------|---------|
| **螢幕錄影（主體）** | 70–80% | 所有操作步驟 |
| **AI 生成插畫或動態插畫** | 5–10% | 開場、概念解釋、故事主角登場、章節轉換 |
| **B-roll（庫存影片或官方宣傳片）** | 5–10% | 開場蒙太奇、抽象概念（例如程式碼雨代表「程式碼生成」） |
| **標題卡或動態圖卡** | 3–5% | 工具名稱卡、章節卡 |

## 二、螢幕錄影的處理（Papaya 的關鍵差異）

1. **系統環境**：macOS，淺色模式，瀏覽器乾淨（沒有一堆分頁和書籤），桌面乾淨
2. **錄製解析度**：高解析度全螢幕錄製，後製時再裁切和放大
3. **鏡頭推拉**（最重要）：
   - 不會整部片都停在全螢幕畫面
   - 操作前先放大到滑鼠附近的區域（放大 1.5–2.5 倍），操作完再平滑拉回全景
   - 使用 ease-in-out 緩動，每次推拉約 0.5–0.8 秒
   - 工具：Screen Studio（Mac）、Cursorful、FocuSee、Camtasia 的 Zoom-n-Pan、DaVinci 關鍵影格
4. **滑鼠游標**：放大且平滑化，點擊時有輕微的漣漪效果
5. **等待畫面全部剪掉**：AI 生成、安裝、下載的過程直接跳剪，只留下旁白「過了一會兒」

## 三、畫面標註元素（貼圖、UI 疊加）

| 元素 | 樣式 | 時機 |
|------|------|------|
| **網址標籤** | 右下角的圓角矩形，**磚橘色 #C8553D 或品牌色**底、白字（例如 `https://claude.ai/`）；在 GitHub 頁面則是藍底白字，貼著網址列下方 | 第一次提到某網站時，停留 3–5 秒 |
| **章節角標** | 右下角，深色半透明底，左側有一條藍色直線，白字「TIP 2 動畫調整」 | 技巧型影片每個技巧開始時，停留約 5 秒 |

| **提示詞卡片** | 把提示詞內容做成浮動的白色卡片，放在畫面中央（圓角、陰影），畫面背景調暗 | 送出提示詞之前 |
| **故事角色插畫** | 全螢幕 AI 插畫，帶輕微動態 | 章節轉換（例如「小杰」） |
| **字幕** | **不壓在畫面上**，改用 YouTube 人工上傳的 CC 字幕（zh-TW），每行 12–13 字 | 全片 |

## 四、AI 插畫的風格
- **LLM Wiki**：Pixar／日系柔和 3D 風格，暖色光，粉彩色調（女孩、白色機器人、未來圖書館、穿運動外套的高中生）

- **Claude Design**：暖木色桌面、日光陰影、螢幕上顯示 UI（產品攝影風）

## 五、轉場
- 螢幕錄影之間：直接硬切，或極短的交叉溶解
- 進出插畫和 B-roll：溶解，或輕微的縮放模糊

- 整體調性：**不用花俏轉場**（沒有旋轉、翻頁、閃白）

# 08 音樂、音效、片尾與互動

> **我們的決定（2026-09-29）**：音樂與音效**只用免費、非商用授權（不需付費購買授權）的素材**，風格**儘量柔和、輕鬆、簡單**。

## 素材來源（免費、非商用授權）
| 來源 | 用途 | 授權注意 |
|------|------|---------|
| YouTube 工作室「音效庫」 | BGM、音效 | 首選；篩選「不需要標示出處」的曲目最省事 |
| Pixabay Music / Pixabay Sound Effects | BGM、音效 | Pixabay License，免費，不需標示 |
| Freesound.org | 音效（pop、whoosh、chime） | 只挑 **CC0** 授權；CC-BY 需要在說明欄標示作者 |
| 免費授權的 Lo-fi 創作者 | BGM | 依照各曲目的授權條款在說明欄標示出處 |

**不使用**：Artlist、Envato、Epidemic Sound 這類付費商用訂閱。
**每支影片**都要在 `專案/2_製作中/` 記錄曲名、來源網址與授權類型，避免日後有版權爭議。

## 一、片頭音效
- Papaya 的原版是約 4–5 秒的 Logo sting，搭配筆刷飛入、圓環擴散的畫面
- **我們的版本**：1 個輕柔的 whoosh，加 1 個柔和的 chime 或鈴聲，2–3 秒內結束
- 風格：柔和、乾淨、簡單，不要強烈的「砰」撞擊聲，也不要科技電子音牆
- 搜尋關鍵字：「soft whoosh」「gentle chime」「soft bell」「minimal intro」

## 二、背景音樂（BGM）
- 曲風：**柔和、輕鬆、簡單**，例如 Lo-fi、輕原聲吉他、鋼琴、Ukulele、輕柔電子
- 不要選：節奏強烈的 EDM、史詩配樂，或企業廣告感太重的配樂
- 選曲條件：沒有人聲；旋律簡單、重複；BPM 大約 70–100；沒有突然的高潮或鼓點
- 音量：比人聲低 18–24 dB（人聲約 -14 LUFS，BGM 大約壓在 -32 至 -36 LUFS），**幾乎察覺不到，但能填補安靜**
- 開場蒙太奇時 BGM 可以稍微大聲，招呼之後壓低（ducking）
- 一支影片用 1–2 首曲子循環；建議建立 3–5 首固定曲目庫，讓頻道形成一致的聲音印象
- 搜尋關鍵字：「lofi chill」「soft acoustic」「calm piano」「light ukulele」「background tutorial」

## 三、音效（SFX）
- 很節制：只在 UI 彈出、標籤出現時用**非常輕**的「pop」或「whoosh」（音量比 BGM 再低一點）
- 一支影片大約 10–20 個音效就夠了，不必每個動作都配音效
- 不使用搞笑罐頭音效、不用「登登登」、也不用笑聲

> ⚠️ 限制：因為下載限制，本分析無法取得原始音軌，以上根據畫面與觀看經驗推定，建議你實際聆聽 2–3 支影片的前 30 秒再校正（請見 09_觀察限制與待確認事項）。
