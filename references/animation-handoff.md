# 生活化動畫與影片素材交付

依序完成指令碼、分鏡、角色、素材提示詞、實測證據與製作包。先讀 fixed-settings.md 與本次頻道設定；使用者本次要求優先。此流程適用動畫解說、工具實測及要求交給 Claude Code／Codex 製作的專案。

需要可重用動畫模組、材質模板、片頭選项或錄屏混合時，另讀 [advanced-animation.md](advanced-animation.md)。本文件繼續管理素材交接與ZIP；進階模組規格不取代既有核定聲線、角色與正式交付目錄。

## 生活例子與故事

用一個工作或生活任務串起全片，例如準備校外教學、整理廚房、批改作文或木工工作檯。先寫「觀眾問題→生活例子→正式概念→操作或觀察→驗收」；每個例子都註明對應概念與類比邊界。不要讓觀眾誤以為加裝介面等於提升模型能力、顯示差異等於測試透過。

可愛動物或人物需有敘事功能：提出疑問、忘記待辦、指出缺件、展示前後差異。安排前後呼應的小笑點，保留自然停頓；避免滿版文字、持續彈跳、無目的科技粒子與合成聲輪流長篇對話。角色數量、動畫比例與時長依內容調整，不把某一集的 22 鏡、13 素材或 9 分鐘當通用要求。

研究指定創作者時，只提取可觀察的教學結構；未看過指定影片，不宣稱已分析其具體視覺做法。人物、臺詞、分鏡及美術採原創，使用本頻道核定品牌。

## 指令碼與實測

指令碼按鏡號編排，逐段列口播、動作、標註、音效與轉場。時間是剪輯估計；按實際配音、操作等待與閱讀時間校正。前集預告可回放數秒接續，本集冷開場仍須納入既有片頭與時間軸。

尚未實測時，寫成功、部分成功與失敗三種旁白分支；配音前依驗收紀錄只選一種，未知結果標待補。分支、來源、提示詞與導演註解不能混入 TTS 純旁白稿。記錄版本、方案、地區、作業系統、查閱日期與必要許可權；動態產品資訊拍攝前核對官方資料。

每關先定義透過條件與固定資料，再下提示詞；儲存原始回答、錄屏、錯誤和人工更正。分開記錄經過時間、人工操作時間、人工補充／修正次數與產品確認次數。費用、token、工具呼叫次數及訂閱使用限制是不同指標，不互相推算。切離後返回的單次觀察不證明全天可靠。固定測試資料快照需標示，避免與即時進度混淆。

## 分鏡與動畫素材

分鏡表至少列：鏡號、時間、對應旁白、動畫／錄屏／混合／圖卡、構圖動作、鏡頭、字幕、音效、轉場、證據來源、素材 ID 與路徑。

先建立角色表，記錄外觀、服裝、配色、道具、敘事功能及參考圖路徑。**黑熊老師直接沿用 fixed-settings.md 的核定角色，不自行重畫或用生成圖替換**；狐狸、水獺等配角是本集原創概念角色，不宣稱是產品官方吉祥物。角色概念圖尚未核定時標草稿。

要求分鏡圖或需要美術預覽時，使用可用的影像生成能力產生角色參考或多格場景預覽，檢查肢體、服裝、道具與構圖。多格圖只作預覽，不能冒充已完成動畫、準確 UI 或實測成果。每格標識與鏡號對映由後製加入。

動畫提示詞逐素材 ID 輸出，含共同設定與個別設定：比例／解析度、角色參考、背景、單一動作、鏡頭、時長、節奏、留白、首尾停格、禁止項及後製文字。中文提示詞為主，可依工具提供英文版。字幕、品牌名稱與數字後製；真實軟體介面用錄屏。長場景拆成約 5–8 秒短片；參考工具限制調整，不要求一次生成長動畫。共用參考圖及種子只在工具支援時使用。

正式配音、暫定配音、配樂、品牌主持人與片尾沿用 fixed-settings.md。沒有核定 TTS 的雲端環境保留無配音／timing 預覽與待補清單，不能換陌生聲線。動畫音效在分鏡列為建議，現有 sfx 設定未授權啟用時不自行開啟；可在後製依本次授權加入。

## 素材包與製作交接

使用者要求打包或交給 Claude Code／Codex 時，完成必要檔案後製作一份 ZIP，保留原專案相對路徑。不要只有一個大指令碼，須附可直接執行的交接指令與缺件清單。

最低內容：

- README.md：主題、頻道、目標時長、畫面規格、目錄、使用步驟、固定品牌設定和素材缺口。
- START_HERE.md：要求代理讀取指令碼、分鏡、提示詞與參考圖，盤點環境，按既有 build-pipeline 完成時間軸、預覽和驗收；不自動發布。
- 1_製作前/：完整指令碼、分鏡表、角色表、動畫提示詞、剪輯指引、實測提示詞與驗收表（非實測片可省後兩項）。
- 2_製作中/：目前已有的角色／場景預覽、前集結尾、錄屏、配音、字幕與剪輯專案，按需納入，沒有就明確標待補。
- 素材清單.json：每項 path、role、status、required，可附鏡號；只納入需要交付的檔案。
- 包內 BUNDLE_MANIFEST.json 與 MISSING_ASSETS.md：打包工具自動產出實際檔案、SHA-256 與待補專案。

影像生成工具若已自動儲存圖片，直接把已知本機輸出納入使用者要求的 ZIP；不必為顯示而另行下載。同一集先前圖片與附件能讀取就一併打包，不能讀取則列缺件，不虛構路徑。逐項核對 ZIP 內容與 CRC，再儲存最終 ZIP 並提供下載連結；產出物是否儲存依所在環境規則，技能本身不作影片素材儲存。

建立白名單 manifest 後執行：

```bash
python scripts/pack_video_bundle.py --project <影片專案> --manifest <素材清單.json> --out <輸出.zip>
```

Manifest 格式：

```json
{
  "bundle_name": "20261008_主題_製作素材包",
  "files": [
    {"path": "README.md", "role": "使用說明", "status": "ready", "required": true},
    {"path": "START_HERE.md", "role": "製作指令", "status": "ready", "required": true},
    {"path": "1_製作前/02_指令碼.md", "role": "指令碼", "status": "ready", "required": true},
    {"path": "2_製作中/螢幕錄影/第一關.mp4", "role": "實測錄屏", "status": "pending", "required": false}
  ]
}
```

ready 但不存在的必填檔案必須補齊後重跑；已知缺少的素材設 pending，不產生空白影片冒充成品。預覽與最終版分開，預覽可標待補，但正式版不能帶未選分支或虛構資料。對外發布依使用者授權範圍；生成 ZIP 不等於授權上傳影片。套件或服務不能用時，先交付現有可檢查成果與具體缺件，不能宣稱已製作 MP4。
