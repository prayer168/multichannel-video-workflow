# 影片專案與正式交付結構

2026-10-11 使用者定案；兩頻道共用。這份規則取代舊的 `YYYYMMDD_主題/1_製作前/2_製作中/3_製作後` 交付配置。

## 一個主題、四支影片

以「主影片名稱」建立根資料夾；Windows 不允許的檔名字元以 `-` 替換。日期放在正式輸出檔名，不加在主題資料夾前。根目錄下設四個影片資料夾，每支各有三個階段：

```text
主影片名稱/
├─ 01_主影片/
│  ├─ 製作前/
│  │  ├─ 逐字稿.txt
│  │  ├─ 分鏡表.md
│  │  └─ 參考資料/
│  ├─ 製作中/
│  │  ├─ 配音/
│  │  ├─ 圖片與動畫/
│  │  ├─ 螢幕錄影/
│  │  └─ 剪輯專案/
│  └─ 製作後/
│     ├─ 主影片名稱_正式版_YYYYMMDD_HHMMSS.mp4
│     ├─ 上架文案.txt
│     ├─ 最終逐字稿.txt
│     ├─ 縮圖.jpg
│     ├─ 字幕/
│     └─ 臉書宣傳/
├─ 02_Shorts_短片一名稱/
│  ├─ 製作前/
│  ├─ 製作中/
│  └─ 製作後/
├─ 03_Shorts_短片二名稱/
│  ├─ 製作前/
│  ├─ 製作中/
│  └─ 製作後/
└─ 04_Shorts_短片三名稱/
   ├─ 製作前/
   ├─ 製作中/
   └─ 製作後/
```

三支 Shorts 與主影片採相同子目錄與交付規則，使用各自的逐字稿、文案、字幕與縮圖，不直接套用主片文案。若本次只授權部分影片，建立其目錄但標明其餘未製作，不虛構成片。主題根目錄可有 `專案卡.md` 或檔案導覽，素材歸入所屬影片的階段目錄，不再另造多層「上架包/videos/Gemini上架素材」。

## 正式成片與時間戳

- 最終 MP4 直接放在各影片的 `製作後/`，不再套 `輸出成品/`。
- 主片：`主影片名稱_正式版_YYYYMMDD_HHMMSS.mp4`；Shorts：`Shorts_短片名稱_正式版_YYYYMMDD_HHMMSS.mp4`。
- 時戳為正式匯出完成時間，使用 `Asia/Taipei`；整理舊片不得把複製時間冒充原輸出時間。無法確認時在專案卡註明來源及使用的檔案修改時間。
- 重新輸出另存新時戳版本，不覆寫已交付成片；專案卡指出目前應上架哪一檔。預覽、粗剪與退役版本歸入 `製作中/剪輯專案/`，避免與現行正式版混用。

## 每支影片一份上架文案

`製作後/上架文案.txt` 為 UTF-8 純文字，包含完整可直接貼上的四個區段：

```text
【YouTube 標題】
本支影片的最終標題

【說明欄】
摘要、適用對象、主片實際章節、來源與必要製作說明、Hashtag

【標記 Tags】
以逗號分隔，去重複；總長不超過 500 字元

【置頂留言】
本支影片的重點與互動問題
```

不再要求另交 `YouTube標題.txt`、`YouTube說明欄.txt`、`YouTube標記.txt`、`置頂留言.txt` 或上架文案 MD。候選標題與編輯草稿留在 `製作前/`。Shorts 說明欄依該短片內容撰寫，不套主片章節；完整片連結未知時清楚保留待填欄位。社群宣傳檔與字幕仍可獨立存放。

逐字稿獨立：`製作前/逐字稿.txt` 保留拍攝／配音原稿；`製作後/最終逐字稿.txt` 必須與實際成片一致，刪除未使用句子，純旁白不混入上架文案。英文逐字稿按需求另存。

## 舊工具相容與整理

既有 build.py、bear_presenter.py、字幕及臉書工具仍可能硬編碼 `1_製作前`、`2_製作中`、`3_製作後`。未修改及驗證工具前，不可只把輸入路徑改名就宣稱可執行。可在各影片 `製作中/剪輯專案/工具工作區/` 保留舊結構，渲染後將通過影音／字幕檢查的正式輸出歸入新結構並合併四項上架文案。

新結構是正式交付位置，工具工作區是內部中間產物；回報及播放器連結指向正式交付檔。現有專案的搬移另依使用者授權執行：先複製、核對檔案大小與 SHA-256、更新相依路徑，再處理舊檔，不因技能更新自動刪除或重組既有影片專案。
