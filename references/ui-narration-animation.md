# 元件動畫、旁白對齊與講者版面

2.6.0｜2026-10-15。動畫講解、風格化 UI、角色與機構段落製作時讀取；適用兩頻道。這是製作與驗收契約，不是既有 build.py 已支援的新輸入格式。

## 1. 製作目標

畫面要演出旁白正在說的內容與動作。UI 中需要解釋或操作的元件，基本上都要有可見的狀態變化；角色不是貼上去便停住，電腦不是空白螢幕，小遊戲不是只有背景移動。不能用整張圖平移、無目的晃動、隨機按鍵或一成不變的循環，冒充功能與因果動畫。

採用動畫講解時，以動作與物件關係為主，解說文字放字幕。畫面只保留必要的 UI 文字、算式、數字、工具名稱與狀態；不預設加章節框、重點清單和字幕底框。實體電腦邊框、教學裝置及真實 UI 容器按內容保留。

每鏡先列元件清單：component_id、用途、動作／狀態、旁白事件、依賴物件、圖層、首尾狀態及驗收。背景或刻意停留的元件可靜止，但應說明用途；不能為了讓每個像素都動而干擾閱讀與觀察。

## 2. 先把旁白變成可驗證的事件

正式旁白到齊後，依實際音檔建立字詞或語句時間軸。自動轉錄可作起點，重要動詞、輸入值、結果、方向與否定句須回聽核對。旁白換版後重新對齊，不沿用原來的比例時間。

每個事件至少記錄：

| 欄位 | 用途 |
|---|---|
| narration_id / phrase | 對應哪句、哪個動詞或數字 |
| cue_start / cue_end | 原旁白音檔中的實際時間 |
| component_id / action | 哪個元件執行什麼動作 |
| before / after | 可檢查的輸入、畫面與結果 |
| depends_on | 哪個事件或物件先成立 |
| offset / duration / hold | 動作開始偏移、長度與觀察停留 |
| evidence / simulation | 來源與是否為示意或模擬 |
| expected_frame / roi | 檢查哪個實際影格與區域 |

局部時間、旁白時間與全片時間分開記錄；全片時間包含片頭。30fps 的動作觸發以逐格對齊為目標，初始驗收容差可設 ±0.15 秒，依語速與動作調整並記錄。結果不可在對應輸入、運算或旁白資訊之前出現；不能單靠「鏡頭長度的三分之一」安排語意事件。

同步分成兩層：

- **語意動作**：輸入、點擊、開關、傳送、加速、比較、結果，必須依旁白事件觸發。
- **持續動作**：呼吸、眨眼、細微擺手、運作中的機構與步態，依情境持續；旁白要求停下、觀察或顯示結果時有意減速或停留。持續動作不能取代語意對齊。

## 3. 元件行為標準

| 元件 | 應呈現的行為 | 不能接受的替代 |
|---|---|---|
| 木偶或角色 | 頭部、身體與四肢分件；轉頭、搖頭、觀察、擺手、重心或步伐有關節；出現後保留自然動態 | 整張貼圖漂移；頭、手或腳與身體斷開；用無目的彈跳充數 |
| 按鈕與鍵盤 | 可見按下／抬起；操作的按鍵、顯示內容和結果互相一致 | 隨機亮鍵，畫面卻顯示另一組輸入 |
| 電腦螢幕 | 依旁白顯示輸入、游標、程式更新、圖片或操作狀態；有開始、過程和結果 | 空白螢幕；只畫外框；假進度與結果無關 |
| 機關、齒輪與連桿 | 運作時所有相依零件共用狀態與接點；齒比、轉向、連桿長度與滑台符合設定 | 齒輪各轉各的；只讓小鳥獨立上下晃；接點滑開 |
| 小鳥等被帶動物 | 與機構的連接點固定，隨滑台／連桿運動；可另加克制反應 | 動作和驅動機關沒有關聯 |
| 恐龍或遊戲角色 | 角色自身有步態、關節或姿勢變化，配合地面、障礙物、跳躍和速度狀態 | 只有背景往後移；裁斷腳後留下懸空的肢體 |
| 速度旋鈕與控制器 | 旁白提到旋鈕、加速或設定時，實際顯示對應操作；單位與初值有來源 | 說旋鈕在轉，畫面卻沒有旋鈕；把內部數值當真實單位 |
| 剪貼簿與資料流 | 來源選取→文字與格式同包→傳送→目的地貼上；保留資料與格式對應 | 沒有來源的紙片亂飛；傳送前先出現完成結果 |

首尾循環應接得上，隨機效果固定種子，依影格時間計算。保留原素材與分件對照；分件後逐格檢查關節遮擋、透明邊緣與接觸陰影。美術一致不只是同一顏色：頭、身體、四肢的材質與光線也要一致。

## 4. 風格化 UI 模擬與真實證據

AI Watch 解說真實功能與操作，仍優先使用實際錄屏。需要木質等風格化解說時，可做自製程式模擬；於案例起始字幕及來源紀錄標示「木質程式模擬／概念示意」。它不能冒充官方原介面、親自實測或完整產品還原。

計算、程式狀態與畫面動作必須一致。例如：

- 輸入 200 → 選加法 → 輸入 10% → 顯示對應案例的 220。
- 解釋百分比時，先顯示 200 × 10% 得到 20；說「再加回去」時切成 200 + 20 得到 220。不可讓 200 × 10% 的結果欄直接跳成 220。
- 換乘法情境時，將 10% 轉為 0.1，再顯示 200 × 0.1 得到 20。
- 旁白說文字「還有格式」時，兩者均須出現在同一資料包，最後目的地也保留兩者。

案例中的版本、規則與數值仍需查證；數字與文字由程式或後製加入。自然教室的示意比例、方向、因果與過程依科學原理，類比另交代邊界。

## 5. 左講者、右動畫

進階動畫講解可選 `presenter_left_stage_right`，適合讓黑熊老師像在現場講解：

- 沿用核定黑熊角色、服裝、聲線與片頭片尾，將講者放左側、主動畫放右側；既有右下角模式保留給適合的錄屏／實拍配置。
- 1080p 的起始提案：講者區 x=40–610、y=190–820，講者約原版 1.5–1.8 倍；右側動畫約 x=620–1820、y=100–820；字幕約 x=120–1800、y=900–1030。以實際不透明邊界驗收，不以 PNG 空白外框代替角色尺寸。
- 講者與主要動畫的視覺中心對齊；指揮棒朝內容，重要操作時點配合語意手勢或目標高亮。多個目標需記錄 target_id，不能固定指錯方向。
- 放大優先從核定 SVG／分層來源重新渲染；既有點陣放大須檢查清晰度。不可鏡像文字與 Logo 來遷就版面。
- 主動畫用透明圖層重排，再合回背景；不要整塊裁出背景一起平移，產生可見矩形接縫。字幕最後疊一次，主持也只疊一次。
- 舊 bear_presenter.py 的預設仍為右下；新位置需明確做合成／轉接並看實際輸出，不能只加未被解析的 JSON 欄位便宣稱生效。

## 6. 工具與回退

可精準控制的 UI、文字、數字、機構與狀態用程式或剪輯工具完成。角色表情、走動或自然動作若分件做法達不到品質，依 [ai-animation.md](ai-animation.md) 使用 Google Flow 補段，再按旁白剪接。先確認可操作的頁面與帳號能力，不預設固定額度，不自行升級方案。

Flow 段落以同一角色及場景參考生成短動作，預留字幕和主持區，避免生成另一個主持人、亂碼與多餘肢體。下載原始檔並保存提示詞與來源後，先驗收再剪入；原生成音訊不自動取代核定配音或混音。生成完成但無法下載，應列缺件，不能宣稱已整合。若程式分件已達品質，不強制改用 Flow。

## 7. 代表預覽與逐句驗收

大量輸出前，選真正有操作與結果的代表片段，至少能看到角色動態、UI 輸入與結果、相依機構或移動物。預覽可節錄多段，但不得以靜態分鏡代替動畫驗收；已授權完整製作時不另加確認關卡。

驗收表：narration_id｜實際起訖｜動詞／數值｜component_id｜預期動作｜實際影格｜首尾狀態｜誤差｜結果／修正。

1. **語意**：逐句核對說什麼就演什麼，包含方向、順序、條件、否定、物件與結果；特別檢查旁白說到但畫面遺漏的控制器或動作。
2. **狀態**：按鍵、輸入欄、程式更新與輸出一致；機關接點和資料依賴成立，數字無前後矛盾。
3. **動態**：對角色頭／四肢、鍵盤、螢幕、機關、遊戲角色分別取 ROI，比較非相鄰影格，確認各元件真的動；像素差非零只能證明有變化，還要目視檢查是否演對內容。
4. **對齊**：在重要提示詞前、動作中、結果後抽查實際編碼影格並回聽；只核對腳本或百分比時間不算通過。
5. **版面**：用手機縮圖檢查字幕、講者、棒端與 UI；不遮擋操作，沒有多餘框架、斷肢、透明接縫或重複主持。
6. **輸出**：品牌、總時長、比例、fps、聲音接點及完整解碼；預覽與正式版分開。報告區分自動驗證、抽查與完整人工審片，不把抽查說成逐格全檢。

若尚未實作通用元件引擎，先在單集管線完成對應渲染與合成，保留可修改素材和時間軸。不要將私人單集素材、個人路徑或未完成的大型渲染器一併封入公開技能。
