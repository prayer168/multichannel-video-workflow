# 長片逐章製作與審片修正（2.41.0）

長篇科普片（例如《尼莫點》約 20 分鐘、11 章）一章一章做：**做完一章 → 擦聲檢核 0 處 → 交使用者審 → 照回饋改 → 下一章**。本檔收錄 2026-11-25《尼莫點》CH01 v0.5→v0.7 使用者審片後定下的四項修正。分鏡、授權與關卡仍照 `blackbear-science-video/SKILL.md`；配音固定設定照 `fixed-settings.md` 第一節。

## 一、每章交付前必做：擦聲檢核（使用者：「做完之後，再麻煩檢查有沒有擦聲，ok 後，就可以做下一章」）

1. **逐檔**：這一章每個配音檔（黑熊老師與小熊）都跑
   `python scripts/build/narration_noise_check.py <配音.wav>`。
2. **整章人聲軌**：照時間軸把配音疊成一軌再跑一次（成片有音樂與音效，不能直接拿成片檢查）：
   `python scripts/build/voice_stem_from_timing.py <timing_full.json> <章節> <remotion/public> 人聲軌.wav`
   `python scripts/build/narration_noise_check.py 人聲軌.wav`
3. 有「摩擦／爆音」或「句中換氣／擦聲」：先把原檔備份到 `_pre_breath/`，再 `--fix` 寫回，重跑到 **兩類都 0 處**。只做靜音、不剪長度，時間軸不用重排。
4. 「其他」類只列出，要確認是不是真的語音（例如句首的「今」、句尾的「嗎」）。
5. 重新渲染後再用 whisper.cpp 確認每句都在（`narration_word_timing.py` 的 WHISPER_DIR），響度 −14±1.5 LUFS。
6. **兩類都 0 處才交片、才開始下一章**；交片時在章節變更紀錄寫出抓到幾處、在哪、怎麼修。

為什麼要兩層：《尼莫點》CH01 v0.6 舊版工具回報 0 處，使用者還是聽到擦聲。原因有二，2.41.0 已修：
- 小熊「……呼叫太空總署？」檔尾的爆音中間夾一格靜音，被切成兩段，前後都不夠安靜而漏掉 → 相隔 ≤ 60 ms 的爆音先併段。
- 快語速時句間停頓只有約 0.2 秒，換氣緊貼前後的字（比人聲低 15–29 dB、長 0.24–0.34 秒），切句的 `tidy()` 抓不到 → 新增「句中換氣／擦聲」：說話段之間、比人聲低 14–42 dB、連續 ≥ 0.12 秒且沒有音高的聲響。
`gemini_tts.py` 2.41.0 起切句後會自動跑同一套清理（`report.json` 的 `muted` 記錄每句靜音幾處），但仍要做上面的逐檔與整章複檢。

## 二、語速與節奏（使用者：「語速有一點太緩慢，讓人看了會想睡著」）

- 語速**只能改 Style 重新產生**，不可事後拉速（`fixed-settings.md` 第一節踩坑紀錄）。
  `python scripts/build/gemini_tts.py --lines 旁白.json --out 配音 --pace fast`
  `--pace fast` 把語速句改成「每分鐘約 320 到 340 字，句與句之間緊湊銜接」、行尾停頓改約 0.2 秒。實測 278 → 約 304 字／分，亮度中位數 1359 → 1373 Hz，仍在核定範圍（1200～1560），聽起來還是黑熊老師。使用者核可（CH01 v0.6「這版不錯」）。
- 產生後先量語速與亮度，跟核定樣本比聽；亮度超過約 1560 就退回一般語速。
- **鏡長跟著配音走**：有旁白的鏡最多比配音多留 1 秒；純畫面鏡縮成規劃的 70%（至少 5 秒）；句間 0.2 秒、鏡頭頭 0.25 秒、尾 0.4 秒。全片總長以實際配音為準（會比規劃短）。
- 使用者指定要放慢的句子（例如懸念句「你信嗎？」）保留放慢，寫進時間軸腳本的例外表。

## 三、依旁白加動態元件（使用者：「針對旁白增加一些動態元件，盡量讓動畫豐富」）

- 每句旁白的**方向詞、數字、名稱、轉折詞**都要有對應的動態元件，在說到那個詞時出現：方向詞→箭頭依序射出；數字→數字從 0 滾動（加單位）；距離→圈或尺擴張；否定／反轉→打叉或蓋章（「不是！」）；名稱或座標→逐字打出、彈出並推鏡；懸念→卡片內容用問號。
- 關鍵詞時間：有 `words.json` 用逐字時間；沒有時用「字在句中的位置 ÷ 句長 × 配音長度」估算，再看靜幀條確認。
- 底圖仍用真實素材（`real-base-motion-layers.md`），動態元件疊在上面；虛構畫面（例如撥號給太空總署）不放機構標誌、標「示意」。
- 元件不可蓋住字卡、標籤或另一個元件；每個新元件都要抽影格看過。

## 四、對話角色要配音（使用者：「小熊的對話，是不是應該幫牠配音？不然會顯得有點突兀」）

- 腳本裡小熊（或其他角色）有台詞就配音，**字卡保留**。
- 小熊聲線：`gemini_tts.py --speaker cub`（Gemini Laomedeia＋小熊 Style，約 320 字／分）。2026-11-25 比聽 Laomedeia、Puck、Leda：Puck、Leda 長句句尾有爆音，選 Laomedeia。
- 小熊原檔比黑熊老師大聲約 4 dB，混音音量壓到約 0.63。極短句（「蛤？」）字卡至少停 1.2 秒。
- 黑熊老師固定 Achird，不因角色配音而改。

## 五、整片逐章實作的踩坑（2.41.1，《尼莫點》CH02–CH08）

- **Gemini 會整句漏念**：CH07–CH08 一組 398 字的配音漏了三句（「確實能降低……空白區」「這麼做的代價是什麼？有沒有更好」），而且這種檔讓 whisper `-dtw` 對齊卡住 46 分鐘以上。`gemini_tts.py` 對齊已加 15 分鐘逾時；逾時或 `report.json` 有 `missing` 時，用 `main.exe -nt` 轉寫核對，把 `raw_*.wav` 移到 `_rejected/` 重跑（只重產生那一組）。
- **整章人聲軌才抓得到的換氣**：CH04「但」字後的換氣逐檔沒抓到（該檔人聲中位數不同），疊成整章人聲軌才出現。兩層檢查缺一不可。
- **配音要同步到 Remotion 的 public/**：新產生或靜音修過的檔，複製後用 `cmp` 核對 `voice/` 與 `public/voice_*` 一致；CH06 曾因漏複製而算圖失敗。
- **整章一次語音辨識會漏句**：有背景音樂時 whisper 偶爾跳過開頭或短句；漏句時分段重聽或聽人聲軌確認，不要直接判定配音缺句。
- **影片素材長度**：`OffthreadVideo` 的 `playbackRate` × 鏡長不能超過素材長度（4 秒素材撐 10 秒鏡要 ≤ 0.4 倍速），否則後段空白。
- **shot_list 的畫面文字可能比旁白早一鏡**：畫面文字一律依旁白設計，input 不改，差異寫進變更紀錄。
