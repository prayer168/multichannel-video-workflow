## 1. 系統目標與導演決策

品牌固定、內容與材質分開、動畫依概念選擇。每集先寫一句「觀眾看完能……」，再決定動畫，而不是先挑漂亮效果。溫馨感靠角色照顧彼此、自然呼吸與停頓、柔和材質和清楚引導建立。

每鏡指定一個主要視覺焦點，按「注意物件→看到變化→理解結果」安排動作。主持人手勢、文字進場與角色反應不能同時爭搶注意力。只有章節變化或敘事需要才使用材質轉場。原創素材與構圖，不複製參考影片的人物、音樂、台詞。

| 決策 | AI Watch | 自然教室 |
|---|---|---|
| 開場 | 工作困擾、工具成果或使用情境 | 生活現象、觀察問題或小故事 |
| 敘事主線 | 問題→白話類比→真實示範→驗證與限制 | 問題→預測→觀察→解釋→再觀察 |
| 角色用途 | 提問、指出缺件、比較結果 | 提問、觀察、記錄、試做 |
| 證據 | 官方資料、錄屏、原始結果；保留版本與日期 | 科學來源、實拍、實驗紀錄；保留條件與單位 |
| 標示 | 概念示意／官方資訊／實測結果 | 模型示意／實際觀察／實驗結果 |
| 節奏起點 | 解說鏡約 5–9 秒；操作依完成時間 | 解說鏡約 7–12 秒；觀察依現象時間 |
| 類比邊界 | 動畫人格不代表 AI 有意識；示意 UI 不代表真功能 | 可視化粒子、速度與比例不一定等於實際尺度 |
| 結尾 | 回答問題、展示成果、說明適用條件 | 回答問題、整理證據、邀請下一次觀察 |

鏡頭秒數為初始預算，不是硬性上限。既有核定聲線與語速優先；需要較慢理解節奏時，先增加畫面停留、觀察段與句間停頓。

舊 build.py 不會自動讀取新的 channel_id、style_id、module_id；不得直接把新 JSON 丟入而宣稱能執行。先增加「規格檢查＋路徑解析＋模組渲染＋舊 YAML 轉接」，仍使用原有旁白與後製管線。不需先引進新的大型動畫框架；真正需要 3D 或複雜骨架時再評估。

建議架構：

```text
單集需求＋內容與證據
        ↓
品牌設定＋材質模板＋模組規格
        ↓
檢查器（來源、缺件、時長、安全區、核定狀態）
        ↓
逐格渲染 → 動畫段／圖卡 → 舊產生器轉接
        ↓
旁白與混音 → 主持角色 → 明確接入片尾
        ↓
字幕與影音驗收 → 正式交付
```

正式旁白沿用核定 Achird 與 fixed-settings 原文 Style；暫定只用 Windows Zhiwei。模型、服務權限與額度在實作時核對，不將本機文件中的歷史額度當保證。配樂沿用原創 lo-fi，音效預設關閉，逐鏡列出建議即可。AI Watch 片尾按 trends/tools/coding/opensource；自然教室用核定熊掌片尾。

## 6. 畫面、時間與聲音規格

設計主版 1920×1080，30fps；素材按最大顯示尺寸準備，推近素材至少多留20%像素。交付MP4採既有H.264流程、音訊48kHz；有透明疊加需求時先交RGBA PNG影格序列，再選剪輯軟體可讀的透明格式，不使用一般H.264 MP4保存透明度。

座標原點左上；矩形定義為 x,y,w,h。外圍安全邊界96px。主內容建議 x=96–1490、y=96–820；字幕矩形[120,870,1400,130]，最多兩行，初始字級48–56px、每行約20–24中文字，按語意換行。主持保留區[1540,650,360,410]包含安全緩衝；實際邊界依角色影格量測。底部字幕不跨主持區。原主持預設高330px、距右下20px，提案區域不是修改既有腳本的位置設定。

主標72–96px，內文44–56px，深文字配平整淺底。將全畫面縮至384×216人工檢查，字幕應能辨識；若看不清先減字與放大。錄屏縮小後重要UI看不清時切局部放大，標示位置，保留動作前後上下文。

每模組局部時間t從0起算；全片T=片頭長度＋前面模組長度＋t。事件以旁白句ID和事件ID錨定，正式音檔到齊後才解析秒數與影格。來源內部的絕對時間不能直接混用。所有動作由影格計算，隨機抖動固定seed，不用真實時間驅動畫面。定格風格只量化角色姿態，字幕與鏡頭照常平滑。

起始動作設計：進場0.3–0.7秒；重點前0.3–0.6秒停頓；關鍵變化後至少0.8秒停留，再按內容調整。首尾各留0.3–0.5秒可剪接狀態。跨鏡以物件位置或視線方向接續，避免每鏡重置。

旁白先按既有-14 LUFS、BGM -33 LUFS及ducking流程處理，片尾接入後重新量測全片；不能把單一旁白軌響度當全片響度。建議成品真峰值不高於-1 dBTP；實際採既有較保守限幅也可。聽檢句頭、句尾、淡出和片尾音量跳變。不得在語句中段硬切；配音時間超預算先修腳本或延長鏡頭。

## 7. 九種動畫模組契約

所有模組共用圖層：background→objects→actors→teaching_marks→labels→presenter→subtitles。字幕區C=[120,870,1400,130]，主持區P=[1540,650,360,410]；表內C/P必須保留，不代表模組自己重複繪製主持人。若後製疊主持，模組render_presenter=false。通用輸入包括style_id、asset_ids、duration、events、safe_areas、source_ids；輸出包括可剪片段、局部事件表、首尾構圖與檢查報告。

| 模組 | 輸入／參數 | 專用圖層 | 時間軸及首尾狀態 | C/P安排 | 驗收 |
|---|---|---|---|---|---|
| M01 情境登場 | 場景、角色、任務；enter_direction、gaze_target、reaction | 場景／人物／任務道具 | 空景→角色入場→注意道具；尾停在提問姿態，約6–10秒 | 保留C/P，角色在主內容區 | 視線對準目標，入場不遮重點 |

| M07 錄屏混合 | 真錄屏src、in/out、證據；crop、zoom、annotation | 原錄屏／框／標註 | 情境→完整錄屏定位→局部操作→結果；約依原操作長度 | UI避P，字幕C；必要時切局部畫面 | 不生成假UI；裁切不刪錯誤或改結果 |

## 8. 配置架構與參數示例

下列JSON是資料設計範例，尚無可直接執行的對應解析器。資料分五部分：project（單集）／content（旁白與證據）／style（美術）／modules（動作）／brand（核定資產）。資產以ID查manifest，路徑相對單集資料夾；舊工具以不同根目錄解析時由轉接器輸出確定的絕對路徑。

```json
{
  "schema_version": "0.1-design",
  "project": {"channel_id": "ai-watch", "mode": "insert", "fps": 30, "size": [1920,1080]},
  "style": {"id": "paper", "palette": "warm", "texture_strength": 0.25, "seed": 13},
  "brand": {"intro_id": "classic", "presenter": "approved_blackbear", "render_stage": "post", "outro_id": "tools"},
  "content": {"narration_id": "N01", "text": "先把任務分成三步，再一步一步完成。", "evidence_type": "concept", "source_ids": []},
  "modules": [{
    "id": "M04", "duration_budget": 18,
    "steps": [{"id":"A","label":"準備"},{"id":"B","label":"執行"},{"id":"C","label":"檢查"}],
    "asset_ids": ["PROP_TASK","PROP_CHECK"],
    "events": [{"id":"E1","anchor":"N01:三步","action":"reveal_steps"},{"id":"E2","anchor":"N01:一步一步","action":"activate_sequence"}],
    "layout": {"captions":[120,870,1400,130],"presenter_reserved":[1540,650,360,410]},
    "render_presenter": false
  }]
}
```

錨點由人工核對或語音對齊產生，不能用文字長度推算後就當精準對齊。科學M06另需 initial_state、variables、transition_rule、units、time_scale、source_ids；不提供規則時不能以美術自由補造物理過程。

素材manifest欄位：asset_id、path、role、dimensions、alpha、style_id、character_id、source、license、approval_status、sha256、required、status、used_in_shots。status取ready/pending/rejected；ready而檔案不存在必須失敗。新片頭approval_status=draft，不可用於正式輸出。

## 11. 同一內容的三種材質示範

共同18秒內容：「事情看起來好多？先把任務分成三步：準備、執行、檢查。每完成一步，就停一下，看看結果。一步一步，也能把事情做好。」這是工作方法情境示意；AI Watch可接工具任務，自然教室可接觀察活動。本段不宣稱特定AI或實驗一定成功。

同一構圖、核定黑熊在右下、同一旁白與事件。以下為文字分鏡提案，未渲染預覽。

| 時段／共同動作 | 暖紙小劇場 | 布布陪你學 | 暖光工作室 |
|---|---|---|---|
| 0–3：任務很多 | 數張空白任務紙散在左側，配角略皺眉 | 幾片布卡輕疊，配角停下看向卡片 | 任務卡片堆疊，配角看向待辦 |
| 3–7：分成三步 | 紙卡排成三列，後製加三個標籤 | 布卡沿縫線軌跡排好，標籤用平整底板 | 三張圓角卡排開，線條連接 |
| 7–13：逐步完成 | 一次亮一張，完成後貼勾章 | 一次翻一片布卡，顯示完成標記 | 高亮依序移動，勾選淡入 |
| 13–18：檢查與安心 | 道具停留，配角點頭，保留成果 | 姿態略放鬆，卡片穩定停留 | 最後成果停留，配角輕點頭 |
| 成本與風險 | 中低；紙邊、陰影與裁切需檢查 | 中高；纖維一致、布片變形、角色動作較費工 | 最低；字卡和錄屏最好整合，需防止像簡報 |

後續比較樣片要三版用同一音檔與影格數；比較材質一致、焦點順序、手機可讀、修改時間、渲染時間與素材數，不用一版更多角色造成不公平比較。

## 14. 資料夾與交付

本文件是技能內的進階動畫規格，與單集素材分開管理。系統實作預計使用 styles/、modules/、brand/、schemas/、adapters/、checks/、examples/，不把影片素材混入技能。

單集正式結構沿用：主題/01_主影片/{製作前,製作中,製作後}，另有02、03、04三支Shorts資料夾；未授權的短片標未製作。預覽放製作中/剪輯專案/，最終片、SRT、最終逐字稿與一份上架文案.txt放製作後。時間戳取正式匯出完成的Asia/Taipei時間，重輸出另存。原始素材、來源、裁切表、設定與渲染紀錄保留。

舊產生器使用的1_製作前／2_製作中／3_製作後放在製作中/剪輯專案/工具工作區，轉接器明確轉入轉出；未驗證前不只改資料夾名稱。首次完成代表片段後才能確認這套轉接流程實際可執行。

## 15. 最小可行版本與擴充順序

| 階段 | 實作範圍 | 驗收與退出條件 |
|---|---|---|
| MVP | 原版片頭、既有主持／旁白／片尾；paper和digital；M02/M04/M07/M08；規格檢查與舊工具轉接 | 18秒任務片＋至少一段真錄屏混合輸出；修改標籤可重渲染；無重複主持、路徑與時碼錯誤 |
| 第二階段 | watercolor與felt、M01/M03/M05；素材圖集管理與一致性檢查 | 三材質同片比較完成；角色和素材對照可重用 |
| 第三階段 | M06、wood與clay；科學規則、時間縮放與姿態量化 | 一個科學過程經內容審核；平滑物理與定格角色共存 |
| 第四階段 | 新片頭可比較預覽、M09、模板選擇介面、批次交付 | 選項有draft/approved狀態；切模板不改品牌或聲線 |

成本基準後續記錄：人工修改分鐘、生圖與重生成次數、素材裁切時間、每秒渲染耗時、修正回合。完成一輪才估單集成本與工期。第一支代表樣片建議暖紙或暖光版本，既有片頭直接沿用；新片頭與完整六模板庫在核心管線穩定後擴充。
