# YouTube 長片與三支 Shorts 上架

## 使用者預設

- 2026-11-05 使用者指定：標準批次為 1 支主影片與 3 支 Shorts，同次工作完成全部上傳。主影片上架當天直接公開，Shorts 01、02、03 從隔天起連續三天，每天台灣時間晚上 8 點（Asia/Taipei，UTC+08:00）依序公開。使用者本次另有指定時優先。
- 以本批次開始上架的台灣日期為 D，主影片在 D 公開，Shorts 01 在 D+1 的 20:00、Shorts 02 在 D+2 的 20:00、Shorts 03 在 D+3 的 20:00 排程公開。這裡每天相隔 24 小時。
- 支援「黑熊老師的自然教室」與「AI 觀測站（AI Watch）」。這是兩個不同頻道，不得只因登入了其中一個就視為目標。
- 使用者要求上架指定專案時，這項指示即包含主影片當天公開及 Shorts 依上述時程排程，資料完整且頻道相符就執行，不再逐片要求確認。單純建立技能、整理文案或預檢不構成發布某個專案的指示。
- 使用者指定單支主片或僅 Shorts 時，只處理指定項目。既有主片用實際 video ID 與網址連結，先核實同頻道及可見度。
- 本技能在被呼叫的工作階段內執行；不會自行監看檔案或在背景常駐。定時監看只有另受使用者要求才設定。

## 接收製作成果

優先依使用者指定的專案卡與交付檔辨識正式版。相容既有製作流程：

```text
主題/
  01_主影片/製作後/{正式版.mp4, 上架文案.txt, 縮圖.jpg, 字幕/}
  02_Shorts_名稱/製作後/...
  03_Shorts_名稱/製作後/...
  04_Shorts_名稱/製作後/...
```

各自讀取 `上架文案.txt` 的 `【YouTube 標題】`、`【說明欄】`、`【標記 Tags】`、`【置頂留言】`，保留最終文案、來源、章節及標籤，不把逐字稿貼進說明欄。不因缺少標準資料夾名稱拒絕其他清楚指定的交付格式。不自動重寫已核定文案；只做已授權的連結補入及必要格式整理。

製作端可直接交付 [assets/publish-manifest.example.json](assets/publish-manifest.example.json) 的格式。未提供時由代理整理成專案根目錄的 `youtube-publish.json`；相對路徑以該 JSON 所在位置解析，影片不必搬移。頻道別名不是 YouTube 的 `UC…` 頻道 ID。manifest 的 `items` 可只列本次影片；若保留完整清單，用 `upload_scope` 列出本次 item ID，預檢及上傳只處理此範圍。僅 Shorts 可用 `existing_long_video.video_id` 與 `url` 指定既有主片，Shorts 的 `related_to` 填 `long`。

先找專案記錄與已登入 Studio 核實頻道；只有無法確定目標、正式檔或必要設定時，才一次詢問缺項。建立批次時將 D 存為 batch_upload_date，並將每支 Shorts 的確切排程時間存入 manifest 的 publish_at（含 +08:00）；續作沿用原批次日期與時間。僅 Shorts 且使用既有主片時，D 採本次 Shorts 批次開始上架的台灣日期。資料可推斷時先繼續準備，不逐欄問答。

## 上傳前完成準備

讀 [references/studio-workflow.md](references/studio-workflow.md) 操作與復原規則。使用 `scripts/preflight.py` 檢查 manifest、路徑、文案與檔案指紋；它**不會上傳，也不判斷影像內容**：

```text
python <技能目錄>/scripts/preflight.py <專案>/youtube-publish.json
```

另以可用的 ffprobe／媒體檢視工具讀取真實片長、顯示比例（含旋轉資訊）與可播放性。Shorts 依現行官方規則檢查；截至 2026-11-04 為正方形或直式且不超過 180 秒，9:16 是常用規格而非唯一規格。不能靠 `#Shorts` 把橫式片變成 Shorts；媒體資料不明時不可只信檔名。字幕檢查起迄時間與語言，縮圖核對對應影片。

每支須確定「是否為兒童專屬」及是否需要「變造／合成內容」揭露。從製作資料、內容與使用者既有設定判定；自然科教學不一律等於兒童專屬，使用 AI 也不一律需要揭露。缺少判定依據時問缺項，不為了通過表單一律填否。

預檢通過後提供簡短批次摘要：目標頻道、本次各支標題、主影片公開日期、各支 Shorts 的確切公開日期及台灣時間 20:00、附加字幕／縮圖／播放清單情況，接著執行。這個摘要不增設批准關卡。

## 執行與交付

優先檢查當前工具是否已有足以完成工作的 YouTube connector；沒有時使用 YouTube Studio 已登入的瀏覽器。先讀該環境實際適用的瀏覽器／電腦操作技能與工具文件；不假設任何固定工具存在、不以 HTTP 模擬登入、不抽取瀏覽器憑證。若檔案選取能力不可用，改用可用的桌面原生選檔；仍不可用則明確報告，不能把填好表單稱為上傳成功。

本次包含主片時，先發布主片並核實公開網址，若本次亦包含 Shorts，在同次工作繼續上傳指定項目，依 Shorts 01、02、03 分別設定 D+1、D+2、D+3 的台灣時間 20:00。僅 Shorts 時先核實既有主片。Shorts 說明欄以實際長片網址取代 `{{LONG_VIDEO_URL}}`，再設定 Studio 的「相關影片」指向同頻道長片。說明欄網址不能取代這個功能；進階功能未開通時記錄該步驟未完成，仍可完成本次已授權的影片發布。

主片縮圖依交付上傳；Shorts 自訂封面依當時介面支援程度處理，不承諾可用電腦上傳圖片。字幕為獨立字幕軌，中文使用繁體中文，英文有交付才加。只有明確指定的既有播放清單才加入；不自動新增播放清單。置頂留言保留在交付資料，**使用者另有要求或本次明確啟用發送時才發表與置頂**；兒童專屬等留言不可用時記錄略過。

每支在可取得 video ID 時立刻更新 `youtube-publish-state.json`。每次點擊發布／儲存前記錄 `publish_pending`，主影片成功後再次開啟詳情核對「公開」才記錄 `published`；Shorts 儲存排程後核對日期、時間與時區，記錄 `scheduled`、`publish_at` 及 `timezone`。排程儲存成功即完成本次該支上架工作。詳細欄位與重試規則見參考文件。已公開項目不重傳；斷線或發布結果不明先查 Studio，不能盲目再點或重新上傳。未成功的後續配件獨立補做，不能因此重傳已公開影片。

回報本次各支的實際網址、可見度、各支 Shorts 的確切排程時間與成功／待補／失敗項目，並在專案寫 `YouTube上架結果.md`。僅在介面實際儲存並核實後聲稱完成。發布失敗不自動刪除已發布影片。這次若僅建置或預檢，明確說明未進行實際上架。

## 置頂留言與 Facebook 宣傳

使用者要求置頂留言時，取交付文案的「置頂留言」，以目標頻道身分發表。先查是否已有同文，發布後從該留言的動作選單置頂，核實頁面顯示已由該頻道置頂，再更新 state 的 pinned_comment。留言失敗可獨立續做。

使用者另要求 Facebook 發布時，讀 [references/facebook-workflow.md](references/facebook-workflow.md)。臉書文沿用對應影片的公開時程，主影片宣傳文在 D 當天發布，三支 Shorts 宣傳文同次準備並排程在 D+1、D+2、D+3 的台灣時間 20:00 依序發布。YouTube 上架指示本身只涵蓋 YouTube。發布結果與成片追蹤記錄存於各自影片專案，技能儲存庫保留可重用流程。
