# Facebook 宣傳文發布

適用於一般影片上架的預設 Facebook 宣傳流程；使用者當次排除 Facebook 或指定不同範圍時依其指示。

## 準備與目的地

- 讀取該片「製作後/臉書宣傳/臉書文_中文.txt」與對應分享圖，將 YouTube 連結占位符換成已核實的實際影片網址。
- 預設目的地為個人檔案「陳無敵」https://www.facebook.com/prayer.chen 及社團「AI 實作與創作社群｜AI Build & Create Community」https://www.facebook.com/groups/2276542379794853 。核對個人檔案、社團與發文身分。使用者提供截圖時，可從畫面上的名稱與網址辨識目的地，再於實際頁面核對。目的地仍不明時，一次詢問名稱或網址。
- 查閱本專案的 Facebook發布結果.md 與指定頁面，已有同一影片的貼文時先核實，避免重複發布。

## 發布時程

2026-11-05 使用者指定臉書文比照 YouTube 的公開節奏。沿用影片批次的 batch_upload_date（D）及各支 publish_at，續作保留原時程。

- 主影片宣傳文在 D 當天、YouTube 主影片核實公開後發布。
- Shorts 01、02、03 宣傳文分別在 D+1、D+2、D+3 的台灣時間 20:00（Asia/Taipei，UTC+08:00）發布，與對應 Shorts 同時公開。
- 同次工作準備各支文案與分享圖，使用指定目的地支援的 Facebook 排程功能儲存。所有已授權目的地都套用相同時程，逐處核對。
- Shorts 排程後已有 video ID 時，使用其實際網址準備貼文；原交付文案導回主片的連結則沿用已公開主片。檢查 Shorts 排程已儲存且日期時間相符，再儲存對應 Facebook 排程。
- 若特定目的地沒有可用排程功能，保留該處發布用文案與圖片，記錄待排程及原因，回報使用者以決定替代方式。若原定時間已過，詢問新的時間後再儲存該項，其餘項目可繼續。

## 發布與驗證

1. 優先使用足以完成工作的 connector；否則使用已登入瀏覽器。填入配套文案、實際 YouTube 網址與對應分享圖。
2. 圖片選檔先啟動 filechooser 等待，再點圖片上傳控制。只有圖片區出現時，繼續點該區的新增圖片控制。可用語意控制無反應時，依新截圖定位。
3. 檢查目的地、發文身分、受眾、附件與發布方式。主影片選當天立即發布，Shorts 選排程並逐支核對實際日期、台灣時間 20:00 與平台時區。個人貼文與社團貼文的操作可能不同，逐處確認。
4. 個人貼文沿用使用者已選定的限時動態自動分享設定，不為本批次更動會影響未來貼文的設定；若介面出現不同且無法推定的選項再詢問。付費推廣只有明確要求才啟用。
5. 立即發布後在該目的地核實文案與附件出現，開啟時間戳記取得獨立貼文網址。排程貼文則在排程清單核對文案、圖片、目的地及確切時間，記錄 scheduled。已排程的同一貼文續作時核對原紀錄，避免再次發布。介面顯示待審核時記錄待審核。結果不明先查頁面，再決定是否重試。
6. 將每處貼文網址或排程項目 ID、對應影片、實際發布／已排程／待審狀態、publish_at、timezone 及限時動態選擇寫入影片專案的 Facebook發布結果.md。可取得時保存可辨識目的地與貼文的截圖。

一般上架依上述既定授權處理兩處；使用者當次限制範圍時依其指示。社群發布失敗時保留已成功的其他貼文，按目的地續做。
